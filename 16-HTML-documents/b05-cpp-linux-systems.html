Chương 1 · Getting Started with Linux Systems and the POSIX Standard Lướt

Chương mở đầu dựng bức tranh chung: Linux gồm những tầng nào, chương trình C++ của ta nằm ở đâu, và chuẩn nào quyết định code có chạy được trên một hệ khác hay không. Nếu đã đọc B07 ch 1–3, chương này chủ yếu là ôn; phần đáng giữ là ranh giới giữa chuẩn C++ và POSIX.

1.1 Các tầng của một hệ Linux

 Ứng dụng C++          sensord, gateway, UI       (user space)
 Thư viện C++          libstdc++ / libc++
 Thư viện C            glibc / musl / uClibc-ng
 ─────────────── system call interface ───────────
 Kernel                scheduler, VFS, network stack, driver   (kernel space)

  • User space chạy ở chế độ không đặc quyền; mỗi process có không gian địa chỉ ảo riêng. Muốn kernel làm gì (mở file, tạo thread, gửi gói tin), process phải gọi system call.
  • libc bọc system call thành hàm C (open, read, fork) và thêm hàm thuần user space (printf, malloc, qsort). libstdc++ dựng tiếp lên trên: std::thread gọi pthread_create, std::ofstream gọi open/write, std::chrono::steady_clock::now() gọi clock_gettime(CLOCK_MONOTONIC) (thường qua vDSO, không vào kernel).

1.2 Shell và script

Shell (bash, hoặc ash của BusyBox trên thiết bị) là chương trình user space đọc lệnh, fork + exec chương trình khác, nối pipe, chuyển hướng fd. Sách dành một phần cho script Bash cơ bản; những thứ cần nhớ khi viết script khởi động hay test trên board:

#!/bin/sh
set -eu                         # dừng khi lệnh lỗi hoặc dùng biến chưa đặt
dev=${1:-/dev/ttyS1}            # tham số có giá trị mặc định
if [ ! -c "$dev" ]; then        # -c: là character device
    echo "không có $dev" >&2; exit 1
fi
for f in /sys/class/thermal/thermal_zone*/temp; do
    printf '%s: %s\n' "$f" "$(cat "$f")"
done
./sensord --port "$dev" 2>&1 | logger -t sensord   # stderr gộp vào stdout, đẩy vào syslog
echo "mã thoát của sensord: ${PIPESTATUS[0]:-?}"   # bash; sh thường không có PIPESTATUS
  • Mã thoát $?: 0 là thành công, khác 0 là lỗi. Chương trình C++ trả về từ main hoặc std::exit(n); bị signal giết thì shell báo 128 + số signal (ví dụ 139 = 128 + 11, SIGSEGV).
  • Luôn đặt biến trong dấu nháy kép ("$f") để tên có khoảng trắng không bị tách.
  • Script cho thiết bị nên viết cho /bin/sh POSIX thay vì bash nếu image không có bash.

1.4 System call nhìn từ C++

Một system call đi qua: hàm wrapper của libc → đặt số syscall và tham số vào thanh ghi → lệnh trap (svc #0 trên ARM64, syscall trên x86-64) → kernel xử lý → trả về. Quy ước lỗi: wrapper trả -1 và đặt errno (chương 5 sẽ chuyển nó thành std::error_code).

#include <fcntl.h>
#include <unistd.h>
int fd = ::open("/sys/class/leds/led0/brightness", O_WRONLY | O_CLOEXEC);
if (fd == -1) { /* errno cho biết lý do */ }
::write(fd, "1", 1);
::close(fd);
  • Dùng :: trước tên POSIX để phân biệt với hàm thành viên cùng tên (File::open, Socket::close) và nhấn mạnh đây là hàm toàn cục của C.
  • strace ./app in mọi syscall mà chương trình C++ gọi (B07 phụ lục A). Rất hữu ích để thấy std::ifstream hay std::thread thực ra làm gì.
  • Chi phí: một syscall tốn vài trăm ns tới vài µs. Vì vậy std::ofstream có buffer, và ghi log từng byte bằng ::write là sai lầm hiệu năng kinh điển.

1.5 Biên dịch chương trình C++ cho Linux

g++ -std=c++20 -O2 -g -Wall -Wextra -pthread -o sensord main.cpp
aarch64-linux-gnu-g++ -std=c++20 -O2 --sysroot=$SDK/sysroot -o sensord main.cpp   # cross-compile
  • -pthread cho mọi chương trình dùng thread (đặt cả macro lẫn cờ link).
  • Từ glibc 2.34, librt, libpthread, libdl đã gộp vào libc; trên toolchain cũ hơn vẫn cần -lrt cho mq_open, shm_open, timer_create.
  • std::filesystem trên GCC 8 cần -lstdc++fs; từ GCC 9 thì không.

Tự kiểm traMột service C++ thoát với mã 134 trong log của systemd. Điều gì đã xảy ra?

134 = 128 + 6, tức SIGABRT. Thường do std::terminate (exception không được bắt, std::thread joinable bị hủy), assert thất bại, hoặc glibc phát hiện heap hỏng (free(): invalid pointer) rồi gọi abort.

Tự kiểm traVì sao không nên dùng fork hay mmap trực tiếp ở tầng logic nghiệp vụ?

Chúng là POSIX, không có trong chuẩn C++: code đó không test được trên nền khác, khó mock, và trộn lỗi hệ điều hành với logic. Gom chúng vào lớp bọc (ví dụ Process, SharedMemory) có interface C++ thuần, logic chỉ dùng interface đó.

Chương 2 · Learning More about Process Management Đọc kỹ

Process là đơn vị cô lập của Linux: không gian địa chỉ riêng, bảng fd riêng, credential riêng. Với một gateway embedded, kiến trúc thường là vài process (mỗi service một process, systemd quản lý), mỗi process vài thread. Chương này đi qua vòng đời process từ góc nhìn C++: tạo, nạp chương trình, bộ nhớ, lập lịch, kết thúc và điều gì xảy ra với destructor ở mỗi kiểu kết thúc.

2.1 Process và thread trong kernel

Kernel Linux không phân biệt cứng process và thread: cả hai là task (struct task_struct), tạo bằng clone() với các cờ chọn chia sẻ gì.

2.2 Tạo process: fork, exec, posix_spawn

  • fork() nhân bản process gọi: con nhận bản sao bộ nhớ (copy-on-write), fd, signal disposition. Trả 0 ở con, PID con ở cha, -1 khi lỗi.
  • exec*() thay chương trình đang chạy bằng chương trình khác, giữ PID và fd không có FD_CLOEXEC. Không bao giờ trả về khi thành công.
  • posix_spawn() gộp hai bước, cho phép khai báo trước các thao tác fd (đóng, dup2, mở) và thuộc tính (signal mask, process group). Trên Linux glibc hiện thực bằng clone(CLONE_VM | CLONE_VFORK), không copy page table, nên nhanh và an toàn hơn fork khi process cha lớn hoặc có nhiều thread.
Cẩn thận`fork` trong chương trình C++ đa luồng

Sau fork, con chỉ còn đúng thread đã gọi. Mọi mutex mà thread khác đang giữ (kể cả khóa bên trong malloc, std::cout, logger) kẹt vĩnh viễn trong con. Giữa fork và exec, con chỉ được gọi hàm async-signal-safe: không new, không std::string, không std::cout, không ném exception. Quy tắc thực dụng: chương trình C++ có thread thì dùng posix_spawn, hoặc fork rồi exec ngay với dữ liệu đã chuẩn bị sẵn trước fork.

Ví dụ: lớp bọc nhỏ chạy một lệnh bằng posix_spawnp, chuyển stdout của con vào pipe, đọc kết quả, trả về mã thoát. Mọi chuỗi argv được dựng trước khi spawn.

#include <fcntl.h>
#include <spawn.h>
#include <sys/wait.h>
#include <unistd.h>
#include <cerrno>
#include <cstdio>
#include <optional>
#include <string>
#include <vector>

extern char **environ;

struct RunResult { int exit_code; std::string output; };

// Chạy lệnh, gom stdout. Trả nullopt nếu không spawn được.
std::optional<RunResult> run(const std::vector<std::string> &args)
{
    std::vector<char *> argv;
    for (auto &a : args) argv.push_back(const_cast<char *>(a.c_str()));
    argv.push_back(nullptr);

    int p[2];
    if (::pipe2(p, O_CLOEXEC) == -1) return std::nullopt;

    posix_spawn_file_actions_t fa;
    posix_spawn_file_actions_init(&fa);
    posix_spawn_file_actions_adddup2(&fa, p[1], STDOUT_FILENO);  // dup2 xóa CLOEXEC trên fd 1

    pid_t pid;
    int rc = posix_spawnp(&pid, argv[0], &fa, nullptr, argv.data(), environ);
    posix_spawn_file_actions_destroy(&fa);
    ::close(p[1]);                                   // cha phải đóng đầu ghi, nếu không đọc không gặp EOF
    if (rc != 0) { ::close(p[0]); return std::nullopt; }  // posix_spawn trả mã lỗi, không đặt errno

    std::string out;
    char buf[256];
    ssize_t n;
    while ((n = ::read(p[0], buf, sizeof buf)) > 0) out.append(buf, n);
    ::close(p[0]);

    int st;
    while (::waitpid(pid, &st, 0) == -1 && errno == EINTR) {}
    int code = WIFEXITED(st) ? WEXITSTATUS(st) : 128 + WTERMSIG(st);
    return RunResult{code, out};
}

int main()
{
    auto r1 = run({"sh", "-c", "echo sensor0; echo sensor1; exit 3"});
    auto r2 = run({"khong-co-lenh-nay"});
    if (!r1) return 1;
    std::printf("mã thoát %d, output:\n%s", r1->exit_code, r1->output.c_str());
    std::printf("lệnh không tồn tại: %s\n",
                !r2 ? "spawn thất bại" : ("mã " + std::to_string(r2->exit_code)).c_str());
    return r1->exit_code == 3 && r1->output == "sensor0\nsensor1\n" ? 0 : 1;
}

Hai chi tiết đáng chú ý: posix_spawn báo lỗi bằng giá trị trả về (như họ pthread), và trên glibc lỗi exec (lệnh không tồn tại) được báo ngay qua giá trị trả về chứ không phải mã thoát 127 như khi tự fork+exec.

2.5 Kết thúc process và destructor

Đây là phần riêng của C++ mà sách C không nói: cách kết thúc quyết định destructor nào chạy.

Cách kết thúc Destructor object cục bộ (stack) Destructor static/global, atexit Xả buffer stdio/iostream
return từ main có có có
std::exit(n) không (stack không unwind) có có
std::quick_exit(n) không không; chạy at_quick_exit không

Hệ quả: - Muốn RAII dọn dẹp lúc tắt (đóng file, flush log, nhả lock): để luồng điều khiển trả về từ main. Handler SIGTERM chỉ đặt cờ (hoặc dùng signalfd, chương 8), vòng lặp chính thoát, main trả về. - Process con sau fork thoát bằng _exit, không phải exit: nếu không, destructor static và atexit của cha chạy hai lần, buffer stdio bị xả hai lần (dòng log in đôi). - Destructor static chạy khi các thread khác có thể vẫn đang chạy và dùng object đó: crash lúc tắt. Join mọi thread trước khi main trả về.

#include <sys/wait.h>
#include <unistd.h>
#include <cstdio>
#include <cstdlib>
#include <string>

struct Tracer {
    const char *name;
    ~Tracer() { std::printf("  ~%s\n", name); }
};

Tracer global{"global"};

// Chạy body trong process con, gom output qua pipe để xem destructor nào in ra
std::string in_child(void (*body)())
{
    int p[2];
    if (::pipe(p) == -1) return "pipe lỗi";
    std::fflush(stdout);
    pid_t pid = ::fork();
    if (pid == 0) {
        ::dup2(p[1], STDOUT_FILENO);
        ::close(p[0]); ::close(p[1]);
        body();
        std::_Exit(99);                       // không tới đây
    }
    ::close(p[1]);
    std::string out; char buf[128]; ssize_t n;
    while ((n = ::read(p[0], buf, sizeof buf)) > 0) out.append(buf, n);
    ::close(p[0]);
    ::waitpid(pid, nullptr, 0);
    return out;
}

void via_return_like() { { Tracer local{"local"}; } std::exit(0); }  // local hủy vì ra khỏi scope
void via_exit()        { Tracer local{"local"}; std::exit(0); }       // local KHÔNG hủy
void via_quick_exit()  { Tracer local{"local"}; std::at_quick_exit([] { std::printf("  at_quick_exit\n"); std::fflush(stdout); }); std::quick_exit(0); }
void via__exit()       { Tracer local{"local"}; std::printf("  (buffer chưa xả)"); ::_exit(0); }

int main()
{
    std::string a = in_child(via_return_like), b = in_child(via_exit),
                c = in_child(via_quick_exit), d = in_child(via__exit);
    std::printf("scope kết thúc rồi exit:\n%s", a.c_str());
    std::printf("exit():\n%s", b.c_str());
    std::printf("quick_exit():\n%s", c.c_str());
    std::printf("_exit():\n%s[rỗng]\n", d.c_str());
    bool ok = a == "  ~local\n  ~global\n" && b == "  ~global\n" &&
              c == "  at_quick_exit\n" && d.empty();
    return ok ? 0 : 1;
}

Output _exit() rỗng: chuỗi "(buffer chưa xả)" nằm trong buffer stdio (stdout là pipe nên buffer toàn phần) và biến mất cùng process.

2.6 wait, zombie và orphan

  • Con kết thúc trước khi cha wait: thành zombie (giữ PID và mã thoát). Cha phải waitpid; nếu cha có nhiều con, gom trong vòng waitpid(-1, &st, WNOHANG) khi nhận SIGCHLD.
  • Cha chết trước: con thành orphan, được "nhận nuôi" bởi init (PID 1) hoặc process đã đặt PR_SET_CHILD_SUBREAPER (systemd user instance, container runtime).
  • Từ Linux 5.3, pidfd_open(pid) cho một fd đại diện process: đưa vào epoll để biết khi nào con thoát, không còn race "PID đã bị tái sử dụng" (B07 ch 26).

2.7 Daemon

Daemon là process chạy nền lâu dài, không gắn terminal. Cách cổ điển (double fork, setsid, chdir("/"), đóng fd, umask(0)) mô tả trong B07 ch 37. Trên hệ thống dùng systemd, không làm những bước đó: chạy foreground, log ra stdout/stderr (journald gom), để systemd lo restart, giới hạn tài nguyên, quyền.

Nhiều process (mỗi service một process) cho cô lập lỗi: một service crash không kéo theo service khác, systemd restart riêng nó, có thể chạy với user và capability riêng. Đổi lại tốn RAM hơn (mỗi process vài MB cho libstdc++ và heap) và cần IPC (chương 7). Một process nhiều thread nhẹ hơn nhưng một lỗi bộ nhớ làm sập tất cả. Thiết bị 256 MB RAM trở lên thường chọn nhiều process; thiết bị 64 MB có thể gộp.

Dưới systemd, stdout là pipe/socket nên stdio/iostream buffer toàn phần; dữ liệu chưa xả lúc fork được nhân bản sang con. Con thoát bằng exit (hoặc trả về từ main) nên xả buffer một lần nữa. Trên terminal, stdout buffer theo dòng nên buffer thường đã rỗng lúc fork. Sửa: fflush (và std::cout.flush()) trước fork, con dùng _exit, hoặc tốt hơn là dùng posix_spawn.

Chương 3 · Navigating through the Filesystems Đọc kỹ

"Mọi thứ là file" là nguyên tắc nền của Linux: file thường, thư mục, thiết bị (/dev/ttyS1), thông tin kernel (/proc, /sys), pipe, socket. Chương này học cách C++17 nhìn file system qua std::filesystem, những gì nó không làm được (fd, quyền chi tiết, fsync), và các file đặc biệt dùng cho IPC: pipe và FIFO.

3.1 VFS, inode và các loại file

Kernel có tầng VFS (Virtual File System) che các file system cụ thể (ext4, f2fs, squashfs, tmpfs, procfs, sysfs) sau cùng một giao diện open/read/write/stat.

  • Inode lưu metadata (loại, quyền, chủ, kích thước, thời gian, vị trí block), không lưu tên. Thư mục là bảng ánh xạ tên → số inode. Một inode có thể có nhiều tên (hard link).

3.2 std::filesystem::path

path là kiểu giá trị biểu diễn đường dẫn, không chạm vào đĩa: ghép, tách, đổi đuôi đều là thao tác chuỗi.

namespace fs = std::filesystem;
fs::path dir = "/sys/class/thermal";
fs::path p = dir / "thermal_zone0" / "temp";   // operator/ ghép có dấu /
p.filename();      // "temp"
p.parent_path();   // "/sys/class/thermal/thermal_zone0"
p.stem();          // "temp"     (tên không đuôi)
p.extension();     // ""         ("" nếu không có)
fs::path("fw-2.1.bin").replace_extension(".sig");   // "fw-2.1.sig"
p.is_absolute();   // true
p.lexically_normal();               // gộp "a/./b/../c" thành "a/c" (không truy cập đĩa)
p.lexically_relative("/sys/class"); // "thermal/thermal_zone0/temp"
p.c_str();         // const char* để truyền cho API POSIX

Các hàm truy cập đĩa thì nằm ở namespace: fs::exists, fs::canonical (giải symlink, đường dẫn phải tồn tại), fs::weakly_canonical, fs::absolute.

3.3 Hai dạng báo lỗi: exception và error_code

Gần như mọi hàm std::filesystem có hai overload:

auto sz = fs::file_size(p);              // lỗi: ném fs::filesystem_error (chứa path và error_code)
std::error_code ec;
auto sz2 = fs::file_size(p, ec);         // noexcept; lỗi: ec được đặt, trả về giá trị đặc biệt
if (ec) log("file_size {}: {}", p.c_str(), ec.message());

Chọn overload error_code khi lỗi là chuyện bình thường (file có thể chưa tồn tại, thiết bị có thể bị rút, thư mục /proc/<pid> biến mất giữa chừng) hoặc khi dự án tắt exception (-fno-exceptions). Overload ném exception hợp với lỗi thật sự bất thường. Chương 5 nói kỹ về std::error_code.

  • directory_entry cache kết quả stat mà kernel trả kèm khi đọc thư mục (d_type), nên is_directory() thường không tốn syscall.
  • Range-for dùng operator++ có thể ném exception; muốn hoàn toàn không ném thì dùng vòng lặp increment(ec) như trên.
  • Không theo symlink thư mục trừ khi đặt follow_directory_symlink (tránh vòng lặp vô hạn).

3.6 Ví dụ: quét /sys/class/thermal kiểu sysfs

Sysfs là ví dụ điển hình của "thông tin kernel dưới dạng file": mỗi thuộc tính là một file văn bản nhỏ. Ví dụ dựng một cây giả lập sysfs trong thư mục tạm (vì môi trường test có thể không có cảm biến), rồi quét bằng std::filesystem với error_code, đọc giá trị, và bỏ qua mục hỏng mà không ném exception.

#include <algorithm>
#include <cstdio>

namespace fs = std::filesystem;

struct Zone { std::string name, type; double celsius; };

std::optional<std::string> read_attr(const fs::path &p)
{
    std::ifstream in(p);
    std::string s;
    if (!in || !std::getline(in, s)) return std::nullopt;
    return s;
}

// Quét root/thermal_zone*/{type,temp}; mục thiếu hoặc hỏng thì bỏ qua.
std::vector<Zone> scan_thermal(const fs::path &root)
{
    std::vector<Zone> zones;
    std::error_code ec;
    for (const auto &e : fs::directory_iterator(root, ec)) {
        auto name = e.path().filename().string();
        if (!name.starts_with("thermal_zone")) continue;
        auto type = read_attr(e.path() / "type");
        auto temp = read_attr(e.path() / "temp");
        if (!type || !temp) continue;
        try { zones.push_back({name, *type, std::stoi(*temp) / 1000.0}); }  // millidegree C
        catch (const std::exception &) { /* giá trị không phải số */ }
    }
    if (ec) std::fprintf(stderr, "không mở được %s: %s\n", root.c_str(), ec.message().c_str());
    std::sort(zones.begin(), zones.end(), [](auto &a, auto &b) { return a.name < b.name; });
    return zones;
}

void write_file(const fs::path &p, const std::string &s) { std::ofstream(p) << s << '\n'; }

int main()
{

    fs::create_directories(root / "thermal_zone0");
    fs::create_directories(root / "thermal_zone1");
    fs::create_directories(root / "thermal_zone2");          // thiếu file temp
    fs::create_directories(root / "cooling_device0");        // không phải zone
    write_file(root / "thermal_zone0/type", "cpu-thermal");
    write_file(root / "thermal_zone0/temp", "47250");

3.9 Pipe vô danh

Pipe là kênh byte một chiều trong kernel (buffer mặc định 64 KB trên Linux), có hai fd: đầu đọc và đầu ghi. Chỉ dùng được giữa các process có quan hệ (tạo pipe trước fork/posix_spawn) hoặc giữa các thread.

int p[2];
::pipe2(p, O_CLOEXEC);      // p[0] đọc, p[1] ghi

Ngữ nghĩa cần nhớ (B07 ch 44): đọc pipe rỗng thì chặn; mọi đầu ghi đóng thì đọc trả 0 (EOF); ghi khi không còn đầu đọc thì SIGPIPE/EPIPE; ghi không quá PIPE_BUF (4096 byte) là nguyên tử. Chuẩn C++ không có kiểu pipe hay iostream gắn với fd; ví dụ 2.2 đã dùng pipe để gom stdout của process con.

3.10 FIFO (named pipe)

FIFO là pipe có tên trong file system, nên process không liên quan cũng dùng được: một bên mở để ghi, một bên mở để đọc.

  • Tạo: ::mkfifo("/run/sensord.fifo", 0660) (chuẩn C++ không có hàm tạo FIFO, nhưng fs::is_fifo nhận ra nó).
  • open chặn cho tới khi đầu kia cũng được mở (trừ khi O_NONBLOCK). Đây là bẫy hay gặp: reader mở FIFO trong thread chính và chương trình "treo" ngay khi khởi động.
  • Mở FIFO bằng std::ifstream/std::ofstream được (chúng gọi open), tiện cho dữ liệu văn bản, nhưng mất kiểm soát lỗi và non-blocking.

Ví dụ: hai process giao tiếp qua FIFO. Con là "producer" ghi các dòng đo qua std::ofstream; cha đọc bằng std::ifstream tới EOF.

#include <sys/stat.h>
#include <sys/wait.h>
#include <unistd.h>
#include <cstdio>
#include <filesystem>
#include <fstream>
#include <string>

namespace fs = std::filesystem;

int main()
{
    fs::path fifo = fs::temp_directory_path() / ("b05-" + std::to_string(::getpid()) + ".fifo");
    if (::mkfifo(fifo.c_str(), 0600) == -1) { std::perror("mkfifo"); return 1; }
    std::printf("is_fifo: %d\n", fs::is_fifo(fifo));

    pid_t pid = ::fork();
    if (pid == 0) {
        {
            std::ofstream out(fifo);                 // chặn tới khi có reader
            for (int i = 0; i < 3; i++) out << "temp=" << 40 + i << '\n';
        }                                            // đóng: reader thấy EOF
        ::_exit(0);
    }

    std::ifstream in(fifo);                          // chặn tới khi có writer
    std::string line; int count = 0;
    while (std::getline(in, line)) { std::printf("đọc: %s\n", line.c_str()); count++; }

    int st; ::waitpid(pid, &st, 0);
    fs::remove(fifo);                                // FIFO không tự mất như pipe vô danh
    return count == 3 && WIFEXITED(st) && WEXITSTATUS(st) == 0 ? 0 : 1;
}

Chương 4 · Diving Deep into the C++ Object Lướt

Lập trình hệ thống bằng C++ thực chất là quản lý tài nguyên qua vòng đời object: fd đóng khi object hủy, mutex nhả khi ra khỏi scope, bộ nhớ chia sẻ được unmap khi wrapper chết. Muốn làm đúng, phải biết chính xác object bắt đầu và kết thúc lúc nào. Chương này ôn các quy tắc đó; nếu đã chắc B01 và M03, đọc lướt rồi làm phần Tự kiểm tra.

4.1 Object, storage duration và lifetime

Trong C++, object là một vùng lưu trữ có kiểu, có lifetime. Bốn loại storage duration:

Storage duration Khai báo Bắt đầu Kết thúc
automatic biến cục bộ khi chạy tới khai báo ra khỏi scope (kể cả do exception)
static biến toàn cục, static trước main (toàn cục) hoặc lần đầu chạy qua (static cục bộ) sau main / std::exit, thứ tự ngược
thread thread_local lần đầu dùng trong mỗi thread khi thread kết thúc
dynamic new, make_unique khi new khi delete (smart pointer quyết định)

Lifetime của object bắt đầu khi constructor chạy xong và kết thúc khi destructor bắt đầu. Truy cập object ngoài lifetime là undefined behavior, kể cả khi bộ nhớ còn đó: đây là nguồn gốc của dangling reference, use-after-free, và crash lúc tắt (chương 2.5).

4.2 Khởi tạo

C++ có nhiều cú pháp khởi tạo; các dạng cần phân biệt:

int a;              // default-init: biến cục bộ kiểu cơ bản có giá trị KHÔNG xác định
int b{};            // value-init: 0
int c = 3.7;        // copy-init, chuyển đổi thu hẹp ngầm: 3
int d{3.7};         // lỗi biên dịch: list-init cấm narrowing
struct Cfg { int baud = 115200; bool parity = false; };
Cfg x;                         // dùng default member initializer
Cfg y{.baud = 9600};           // designated initializer (C++20), parity = false
std::vector<int> v1(3, 0);     // 3 phần tử 0
std::vector<int> v2{3, 0};     // 2 phần tử: 3 và 0 (initializer_list thắng)

Thói quen an toàn: luôn khởi tạo ({}), dùng default member initializer cho struct cấu hình, dùng designated initializer để đọc code như cấu hình phần cứng.

Biến toàn cục: kiểu có thể tính lúc biên dịch nên đánh dấu constexpr hoặc constinit (C++20): bảo đảm khởi tạo tĩnh, không phụ thuộc thứ tự giữa các file.

4.3 Temporary và gia hạn lifetime

Temporary (giá trị tạm) sống tới hết full-expression chứa nó. Ngoại lệ: gắn trực tiếp vào const T& hoặc T&& cục bộ thì sống theo tham chiếu đó.

const std::string &s = make_name();            // OK: temporary được gia hạn
std::string_view sv = make_name();             // dangling: string_view không gia hạn gì
const char *p = make_name().c_str();           // dangling ngay sau dấu ;
for (char ch : make_cfg().name) {}             // trước C++23: make_cfg() chết trước vòng lặp

Quy tắc: kiểu "view" (string_view, span, iterator, con trỏ) không bao giờ giữ temporary sống. Đây là lỗi hay gặp nhất khi bọc API C: ::open(make_path().c_str(), ...) thì đúng (cùng full-expression), nhưng lưu c_str() vào biến rồi dùng sau là sai.

4.4 Placement new và object trong vùng nhớ có sẵn

Lập trình hệ thống thường có vùng nhớ đến từ nơi khác: mmap của shared memory, buffer DMA, bộ nhớ thiết bị. Muốn có object C++ ở đó, phải bắt đầu lifetime của nó:

void *mem = ::mmap(nullptr, sizeof(Ring), PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
Ring *r = new (mem) Ring{};    // placement new: chạy constructor trong vùng nhớ đã có
// ... dùng r ...
r->~Ring();                    // gọi destructor thủ công, không delete
::munmap(mem, sizeof(Ring));
  • Với kiểu implicit-lifetime (trivially copyable, aggregate đơn giản), C++20 cho phép object "tự xuất hiện" trong bộ nhớ từ malloc/mmap/memcpy; C++23 thêm std::start_lifetime_as<T>(p) để nói rõ điều đó. Dùng kiểu đơn giản cho dữ liệu trong shared memory là lựa chọn an toàn nhất (chương 7 và 9).
  • Không đặt std::string, std::vector, con trỏ hay object có vtable trong shared memory giữa process: con trỏ chỉ có nghĩa trong không gian địa chỉ của một process.

4.5 Functor

Functor là object có operator(): hàm mang theo trạng thái.

struct InRange {
    int lo, hi;
    bool operator()(int v) const { return v >= lo && v <= hi; }
};
auto bad = std::count_if(samples.begin(), samples.end(), std::not_fn(InRange{-40, 125}));

So với con trỏ hàm: functor có trạng thái, và compiler biết chính xác hàm được gọi nên inline được (con trỏ hàm thường không). Đó là lý do std::sort với lambda nhanh hơn qsort với con trỏ hàm.

4.6 Lambda

Lambda là cú pháp ngắn để tạo functor vô danh: compiler sinh một class có operator(), các biến capture thành thành viên.

int threshold = 80;
auto hot     = [threshold](int t) { return t > threshold; };   // capture copy
auto counter = [n = 0]() mutable { return ++n; };              // init-capture, mutable để sửa bản copy
auto job     = [buf = std::move(buffer)] { send(buf); };       // move vào lambda (chỉ-move)
auto log     = [&](const char *m) { logger.write(m); };        // capture mọi thứ bằng tham chiếu
auto any     = [](auto x, auto y) { return x < y; };           // generic lambda (template)
const auto cfg = [&] {                                         // IIFE: khởi tạo const phức tạp
    Config c; c.load("/etc/sensord.conf"); return c;
}();
Cẩn thậnCapture tham chiếu và vòng đời

[&] trong lambda được lưu lại (callback, std::thread, timer, coroutine) là nguồn dangling số một: biến cục bộ chết khi hàm trả về, lambda vẫn sống. Với callback bất đồng bộ, capture bằng giá trị, hoặc shared_ptr/weak_ptr tới object sở hữu ([self = shared_from_this()]). [this] cũng là capture con trỏ: object có thể chết trước callback.

4.7 std::function và chi phí

std::function<R(Args...)> chứa được mọi callable cùng chữ ký (type erasure). Đổi lại: - Có thể cấp phát heap khi callable lớn hơn bộ đệm nội bộ (libstdc++: 16 byte, tức khoảng hai con trỏ). - Gọi qua con trỏ gián tiếp, không inline được. - Yêu cầu callable copy được (lambda capture unique_ptr không cho vào được); C++23 thêm std::move_only_function.

Trên đường nóng (ISR-like, vòng lặp điều khiển), truyền callable bằng template (template <class F> void for_each_sample(F &&f)), hoặc dùng std::function_ref (C++26) / tự viết "function_ref" không sở hữu.

Tự kiểm trastd::string_view name = cfg.get("port"); với get trả về std::string. Sau đó ::open(std::string(name).c_str(), ...) mở sai file ngẫu nhiên. Vì sao?

get trả về temporary std::string, chết cuối câu lệnh; name trỏ vào bộ nhớ đã giải phóng. Giữ kết quả bằng std::string, hoặc đổi get trả const std::string& tới dữ liệu do cfg sở hữu.

Tự kiểm traMột timer callback được đăng ký bằng timer.on_expire([&] { this->retry(); }) trong method của Connection. Khi kết nối bị hủy, thiết bị thỉnh thoảng crash vài giây sau. Sửa thế nào?

Lambda giữ this (và có thể tham chiếu tới biến cục bộ) nhưng Connection đã bị hủy trước khi timer hết hạn. Hủy timer trong destructor của Connection (RAII cho đăng ký callback), hoặc capture weak_ptr ([w = weak_from_this()] { if (auto s = w.lock()) s->retry(); }).

Chương 5 · Handling Errors with C++ Đọc kỹ

Lỗi trong lập trình hệ thống là chuyện thường ngày: cổng serial bị rút, broker mất kết nối, flash đầy, thiết bị trả EBUSY. Chương này đi từ errno của C tới hệ thống báo lỗi của C++ (std::error_code, std::error_condition, category), cách bọc system call thành exception có nghĩa (std::system_error), chi phí của exception, và RAII để dọn dẹp đúng dù lỗi xảy ra ở đâu.

5.1 errno và giới hạn của nó

int fd = ::open(path, O_RDONLY | O_CLOEXEC);
if (fd == -1) {
    int err = errno;                       // lưu ngay: lời gọi tiếp theo có thể ghi đè
    std::fprintf(stderr, "open %s: %s\n", path, std::strerror(err));
}
  • errno là biến thread-local (mỗi thread một bản), chỉ có nghĩa khi giá trị trả về đã báo lỗi.
  • strerror không thread-safe trên mọi nền tảng; dùng strerror_r, hoặc tốt hơn là std::error_code::message().
  • Nhược điểm: chỉ là một số nguyên, không mang theo ngữ cảnh (file nào, thao tác nào), dễ bị ghi đè, không phân biệt được lỗi POSIX với lỗi của thư viện khác.

5.2 std::error_code và category

std::error_code là cặp (giá trị int, con trỏ tới category). Category cho biết giá trị đó thuộc "không gian lỗi" nào và cách biến nó thành thông điệp.

std::error_code ec(errno, std::system_category());   // lỗi từ system call Linux
ec.value();            // 2
ec.message();          // "No such file or directory"
ec.category().name();  // "system"
if (ec) { /* có lỗi: value != 0 */ }

Các category chuẩn: std::system_category() (errno của OS), std::generic_category() (giá trị POSIX trung lập nền tảng, dùng với std::errc), std::iostream_category(), std::future_category().

5.3 std::error_condition và so sánh di động

error_code là lỗi cụ thể của một nền tảng; error_condition là lớp lỗi để so sánh. std::errc là enum các điều kiện POSIX chuẩn:

if (ec == std::errc::no_such_file_or_directory) { /* tạo file mặc định */ }
if (ec == std::errc::resource_unavailable_try_again) { /* EAGAIN: thử lại */ }

So sánh error_code == errc đi qua category().equivalent(...), nên một category riêng có thể khai báo "lỗi SensorError::bus_busy của tôi tương đương std::errc::device_or_resource_busy". Code tầng trên chỉ cần so với điều kiện chung.

5.4 Tự định nghĩa category cho thư viện của mình

Một driver/thư viện nên có enum lỗi riêng, dùng được ở mọi nơi nhận std::error_code:

#include <cstdio>
#include <string>
#include <system_error>

enum class SensorError { ok = 0, not_found = 1, crc_mismatch, bus_busy, out_of_range };

class SensorCategory : public std::error_category {
public:
    const char *name() const noexcept override { return "sensor"; }
    std::string message(int v) const override {
        switch (static_cast<SensorError>(v)) {
        case SensorError::ok:           return "thành công";
        case SensorError::not_found:    return "không tìm thấy cảm biến";
        case SensorError::crc_mismatch: return "sai CRC";
        case SensorError::bus_busy:     return "bus I2C đang bận";
        case SensorError::out_of_range: return "giá trị ngoài dải đo";
        }
        return "lỗi không xác định";
    }
    // Ánh xạ sang điều kiện chung để tầng trên so sánh di động
    std::error_condition default_error_condition(int v) const noexcept override {
        switch (static_cast<SensorError>(v)) {
        case SensorError::not_found: return std::errc::no_such_device;
        case SensorError::bus_busy:  return std::errc::device_or_resource_busy;
        default:                     return {v, *this};
        }
    }
};

const std::error_category &sensor_category() { static SensorCategory c; return c; }

// Cho phép SensorError chuyển ngầm thành std::error_code
template <> struct std::is_error_code_enum<SensorError> : std::true_type {};
std::error_code make_error_code(SensorError e) { return {static_cast<int>(e), sensor_category()}; }

std::error_code read_sensor(int addr, int &out)
{
    if (addr == 0x48) { out = 2350; return {}; }       // thành công
    if (addr == 0x49) return SensorError::bus_busy;
    return SensorError::not_found;
}

int main()
{
    int addrs[] = {0x48, 0x49, 0x50};
    int busy = 0, missing = 0;
    for (int a : addrs) {
        int v = 0;
        std::error_code ec = read_sensor(a, v);
        if (!ec) { std::printf("0x%02x: %d\n", a, v); continue; }
        std::printf("0x%02x: [%s:%d] %s\n", a, ec.category().name(), ec.value(), ec.message().c_str());
        if (ec == std::errc::device_or_resource_busy) busy++;     // so với điều kiện chung
        if (ec == std::errc::no_such_device) missing++;
    }
    // errno thật cũng so được với cùng điều kiện
    std::error_code sys(EBUSY, std::system_category());
    std::printf("EBUSY == device_or_resource_busy: %d\n", sys == std::errc::device_or_resource_busy);
    return busy == 1 && missing == 1 && sys == std::errc::device_or_resource_busy ? 0 : 1;
}

5.6 RAII cho fd: ví dụ nền tảng

Mọi tài nguyên của OS (fd, mapping, lock, thread) nên được sở hữu bởi một object. UniqueFd dưới đây là kiểu sẽ dùng lại ở các chương sau: chỉ-move, đóng fd trong destructor, constructor ném system_error có ngữ cảnh.

#include <fcntl.h>
#include <unistd.h>
#include <cerrno>
#include <cstdio>
#include <string>
#include <system_error>
#include <utility>

class UniqueFd {
public:
    UniqueFd() = default;
    explicit UniqueFd(int fd) noexcept : fd_(fd) {}
    UniqueFd(const char *path, int flags, mode_t mode = 0644)
        : fd_(::open(path, flags | O_CLOEXEC, mode)) {
        if (fd_ == -1) throw std::system_error(errno, std::system_category(), std::string("open ") + path);
    }
    UniqueFd(UniqueFd &&o) noexcept : fd_(std::exchange(o.fd_, -1)) {}
    UniqueFd &operator=(UniqueFd &&o) noexcept { reset(std::exchange(o.fd_, -1)); return *this; }
    UniqueFd(const UniqueFd &) = delete;
    UniqueFd &operator=(const UniqueFd &) = delete;
    ~UniqueFd() { reset(); }

    int get() const noexcept { return fd_; }
    explicit operator bool() const noexcept { return fd_ != -1; }
    int release() noexcept { return std::exchange(fd_, -1); }
    void reset(int fd = -1) noexcept {
        if (fd_ != -1) ::close(fd_);     // không retry close khi EINTR trên Linux
        fd_ = fd;
    }
private:
    int fd_ = -1;
};

// Ghi đầy đủ, trả error_code thay vì ném (dùng được cả khi -fno-exceptions)
std::error_code write_all(const UniqueFd &fd, std::string_view data)
{
    while (!data.empty()) {
        ssize_t n = ::write(fd.get(), data.data(), data.size());
        if (n == -1) {
            if (errno == EINTR) continue;
            return {errno, std::system_category()};
        }
        data.remove_prefix(static_cast<size_t>(n));
    }
    return {};
}

int count_open_fds() { int n = 0; for (int i = 0; i < 1024; i++) n += ::fcntl(i, F_GETFD) != -1; return n; }

int main()
{
    int base = count_open_fds();
    std::string path = "/tmp/b05-fd-" + std::to_string(::getpid());
    {
        UniqueFd f(path.c_str(), O_WRONLY | O_CREAT | O_TRUNC);
        auto ec = write_all(f, "baud=115200\n");
        std::printf("ghi: %s, fd đang mở thêm: %d\n", ec ? ec.message().c_str() : "ok", count_open_fds() - base);
        UniqueFd moved = std::move(f);                   // chuyển sở hữu, f rỗng
        std::printf("sau move: f=%d moved=%d\n", bool(f), bool(moved));
    }                                                    // moved đóng fd ở đây
    std::printf("sau scope, fd mở thêm: %d\n", count_open_fds() - base);

    bool threw = false;
    try {
        UniqueFd bad("/khong/co/thu-muc/nay", O_RDONLY);
    } catch (const std::system_error &e) {
        threw = e.code() == std::errc::no_such_file_or_directory;
        std::printf("bắt được: %s\n", e.what());
    }
    ::unlink(path.c_str());
    return threw && count_open_fds() == base ? 0 : 1;
}
Ghi chú`close` và `EINTR`

Trên Linux, close luôn giải phóng fd kể cả khi trả EINTR; gọi lại có thể đóng nhầm fd vừa được thread khác mở với cùng số. Vì vậy destructor gọi close một lần và bỏ qua lỗi. Nếu lỗi khi đóng là quan trọng (NFS báo lỗi ghi trễ), hãy fsync trước và kiểm tra lỗi đó.

5.7 Exception: khi nào dùng, chi phí bao nhiêu

  • Mô hình zero-cost (Itanium ABI trên Linux): đường không ném không tốn lệnh nào thêm; bảng unwind nằm trong .eh_frame. Đường ném thì đắt: cấp phát object exception, tra bảng, unwind từng frame, thường hàng µs tới hàng chục µs.
  • Hệ quả: exception hợp với lỗi hiếm, không phục hồi tại chỗ (cấu hình sai lúc khởi động, hết bộ nhớ, bất biến bị phá). Lỗi thường xuyên, xử lý tại chỗ (timeout, EAGAIN, CRC sai, thiết bị bận) nên trả error_code/expected.
  • noexcept: hàm hứa không ném; nếu ném thật, std::terminate được gọi. Destructor mặc định là noexcept. Move constructor nên noexcept để std::vector dùng move khi cấp phát lại.
  • Không được để exception thoát khỏi: destructor, callback được gọi từ code C (thư viện C, signal handler, thread function của pthread), hàm main của thread (std::thread gọi terminate).

5.8 Sau C++20: std::expected

C++23 thêm std::expected<T, E>: hoặc chứa giá trị T, hoặc chứa lỗi E. Gộp "kết quả hoặc error_code" vào một kiểu trả về, kèm các thao tác chuỗi and_then, transform, or_else:

std::expected<int, std::error_code> read_temp(I2cBus &bus);
auto r = read_temp(bus).transform([](int raw) { return raw / 100.0; });
if (!r) log("đọc lỗi: {}", r.error().message());

GCC 12 trở lên có <expected> với -std=c++23. Với C++20, dùng tl::expected (header-only) có API tương tự.

5.9 Chiến lược lỗi cho một service

  1. Tầng gọi system call: chuyển errno thành std::error_code ngay tại chỗ, kèm ngữ cảnh khi ghi log.
  2. Lỗi có thể phục hồi (thử lại, backoff, chuyển trạng thái): trả error_code/expected, xử lý ở tầng gần nhất hiểu được nó.
  3. Lỗi không phục hồi khi khởi động (cấu hình sai, thiếu quyền): ném system_error, bắt ở main, log rõ ràng, thoát mã khác 0 để systemd biết.
  4. Lỗi lập trình (bất biến bị phá): assert hoặc std::abort kèm log; đừng cố chạy tiếp với trạng thái hỏng. Watchdog và systemd sẽ restart.
  5. Mọi tài nguyên giữ bằng RAII, để mọi đường thoát (return sớm, exception) đều dọn dẹp.

Chương này đặt thread của C++ cạnh thread của Linux: std::thread thực chất là gì, vì sao C++20 thêm std::jthread và std::stop_token, các công cụ đồng bộ mới (counting_semaphore, latch, barrier), và cách dừng thread đúng cách trong một daemon. Nếu đã học B02 và M05, đọc lướt 6.1–6.4 và tập trung vào 6.5–6.8.

6.1 Thread của C++ trên Linux

std::thread t(f, args...) gọi pthread_create; mỗi thread là một task của kernel (chương 2.1), có TID riêng, stack riêng (mặc định 8 MB ảo với glibc, chỉ trang được chạm mới tốn RAM), chung bộ nhớ và fd với cả process.

std::thread t(read_uart, std::ref(port), 115200);   // đối số được COPY vào thread; tham chiếu phải std::ref
t.native_handle();                                  // pthread_t, dùng cho priority, affinity, tên
pthread_setname_np(t.native_handle(), "uart-rx");   // tên hiện trong top -H, gdb (tối đa 15 ký tự)
std::thread::hardware_concurrency();                // số CPU khả dụng (gợi ý, có thể 0)
t.join();                                           // chờ xong; hoặc t.detach()

Luật quan trọng nhất: std::thread còn joinable khi bị hủy thì gọi std::terminate. Mọi đường thoát (kể cả exception) phải join hoặc detach. detach gần như luôn là sai trong daemon: không biết thread kết thúc lúc nào, không dọn dẹp được lúc tắt (chương 2.5).

Exception ném ra khỏi hàm của thread cũng gọi std::terminate. Muốn chuyển lỗi về thread khác, bắt trong thread và truyền qua std::promise/std::exception_ptr, hoặc dùng std::async.

6.2 std::jthread và hủy hợp tác

C++20 std::jthread sửa hai nhược điểm của std::thread:

  1. Destructor tự yêu cầu dừng rồi join, không terminate.
  2. Mang theo một std::stop_source; nếu hàm của thread nhận std::stop_token làm tham số đầu, jthread truyền token vào.
std::jthread worker([](std::stop_token st, int period_ms) {
    while (!st.stop_requested()) {
        poll_sensor();
        std::this_thread::sleep_for(std::chrono::milliseconds(period_ms));
    }
}, 100);
worker.request_stop();   // hoặc để destructor tự làm

Đây là hủy hợp tác (cooperative cancellation): thread tự kiểm tra và tự thoát ở điểm an toàn, nên destructor của nó chạy và lock được nhả. Ngược lại, pthread_cancel (B07 ch 32) hủy thread từ bên ngoài ở "cancellation point"; với C++ trên glibc, nó được hiện thực bằng một exception đặc biệt unwind stack, và nếu gặp hàm noexcept thì terminate. Trong code C++, đừng dùng pthread_cancel.

6.3 stop_callback và chờ có thể hủy

Vấn đề: thread đang chặn (chờ condition variable, chờ read, chờ epoll_wait) thì không kiểm tra stop_requested() được. Hai công cụ:

  • std::condition_variable_any::wait(lock, stop_token, pred): tự thức dậy khi có yêu cầu dừng; trả pred() (false nếu thoát vì dừng).
  • std::stop_callback cb(token, fn): đăng ký hàm chạy khi có yêu cầu dừng (chạy ngay trong thread gọi request_stop, hoặc ngay lập tức nếu đã dừng từ trước). Dùng để đánh thức syscall đang chặn: ghi vào eventfd, shutdown một socket, hoặc gửi một message đặc biệt.
std::stop_callback wake(st, [&] { uint64_t one = 1; ::write(event_fd, &one, 8); });
// epoll_wait sẽ thức dậy vì event_fd sẵn sàng

std::call_once / static cục bộ khởi tạo một lần

Trên Linux, std::mutex là pthread_mutex_t, xây trên futex: khóa không tranh chấp chỉ là một lệnh atomic trong user space; chỉ khi tranh chấp mới gọi syscall futex để ngủ. Mutex của C++ không có priority inheritance; thread real-time cần PI phải dùng pthread_mutexattr_setprotocol(PTHREAD_PRIO_INHERIT) trực tiếp (M05).

Chi tiết deadlock, lock hierarchy, spurious wakeup và thiết kế cấu trúc dữ liệu thread-safe xem B02 ch 3–4 và M05.

6.5 Ví dụ: worker có hàng đợi, dừng sạch bằng stop_token

Mẫu "một thread xử lý sự kiện từ hàng đợi" có mặt trong mọi daemon. Hàng đợi dưới đây dùng condition_variable_any với stop_token, nên khi yêu cầu dừng, thread đang chờ thức dậy ngay và thoát. Test chạy với ThreadSanitizer.

Chú ý cách main biết worker đã xử lý xong: dùng std::latch (6.6) chứ không gọi lại pop để "kiểm tra". pop với một token không bao giờ dừng sẽ chặn mãi khi hàng đợi rỗng; đó là bug hay gặp khi viết test cho code đồng bộ. Hàm try_pop không chặn dùng cho việc kiểm tra.

#include <condition_variable>
#include <cstdio>
#include <deque>
#include <latch>
#include <mutex>
#include <optional>
#include <stop_token>
#include <string>
#include <thread>
#include <vector>

template <class T>
class StopQueue {
public:
    void push(T v) {
        { std::lock_guard lk(m_); q_.push_back(std::move(v)); }
        cv_.notify_one();
    }
    std::optional<T> pop(std::stop_token st) {
        std::unique_lock lk(m_);
        if (!cv_.wait(lk, st, [&] { return !q_.empty(); })) return std::nullopt;
        T v = std::move(q_.front()); q_.pop_front();
        return v;
    }
    std::optional<T> try_pop() {                           // không chặn
        std::lock_guard lk(m_);
        if (q_.empty()) return std::nullopt;
        T v = std::move(q_.front()); q_.pop_front();
        return v;
    }
private:
    std::mutex m_;
    std::condition_variable_any cv_;
    std::deque<T> q_;
};

int main()
{
    constexpr int N = 5;
    StopQueue<std::string> q;
    std::vector<std::string> handled;
    std::latch all_done(N);
    bool callback_ran = false;
    {
        std::jthread worker([&](std::stop_token st) {
            std::stop_callback on_stop(st, [&] { callback_ran = true; });
            while (auto msg = q.pop(st)) { handled.push_back(*msg); all_done.count_down(); }
        });
        for (int i = 0; i < N; i++) q.push("frame " + std::to_string(i));
        all_done.wait();                                    // chắc chắn worker đã xử lý đủ N
        if (q.try_pop()) { std::puts("còn phần tử thừa"); return 1; }
    }   // ~jthread: request_stop() + join()

    for (auto &h : handled) std::printf("xử lý: %s\n", h.c_str());
    std::printf("stop_callback đã chạy: %d\n", callback_ran);
    return handled.size() == N && callback_ran ? 0 : 1;
}

Truy cập handled và callback_ran từ main sau khi join là an toàn: join tạo quan hệ happens-before (chương 9). callback_ran được ghi bởi stop_callback, chạy trong thread gọi request_stop (tức main, trong destructor của jthread).

6.6 counting_semaphore, latch, barrier (C++20)

Công cụ Ý nghĩa Ví dụ embedded
std::counting_semaphore<N> / binary_semaphore bộ đếm: acquire giảm (chặn nếu 0), release tăng; không có chủ sở hữu giới hạn 4 request HTTP đồng thời; báo hiệu "có dữ liệu" kiểu ISR → task
std::latch đếm xuống một lần, wait tới khi về 0; không dùng lại chờ mọi driver khởi tạo xong trước khi báo READY cho systemd
std::barrier điểm hẹn lặp lại theo pha, có hàm hoàn tất chạy mỗi pha N thread đọc N cảm biến mỗi chu kỳ, gộp kết quả khi đủ

std::counting_semaphore chỉ dùng giữa các thread trong một process. Semaphore giữa các process vẫn là sem_open/sem_init(pshared=1) của POSIX (chương 7).

#include <array>
#include <atomic>
#include <barrier>
#include <cstdio>
#include <semaphore>
#include <thread>
#include <vector>

int main()
{
    constexpr int SENSORS = 3, CYCLES = 4;
    std::array<int, SENSORS> sample{};            // mỗi thread ghi ô của mình
    std::vector<int> cycle_sum;                   // chỉ hàm hoàn tất ghi

    // Hàm hoàn tất chạy một lần mỗi pha, khi mọi thread đã tới barrier,
    // trước khi bất kỳ thread nào được đi tiếp: đọc sample an toàn.
    std::barrier sync(SENSORS, [&]() noexcept {
        int s = 0; for (int v : sample) s += v;
        cycle_sum.push_back(s);
    });

    std::counting_semaphore<2> bus(2);            // tối đa 2 thread dùng "bus" cùng lúc
    std::atomic<int> on_bus{0}, max_on_bus{0};

    {
        std::vector<std::jthread> ts;
        for (int id = 0; id < SENSORS; id++)
            ts.emplace_back([&, id] {
                for (int c = 0; c < CYCLES; c++) {
                    bus.acquire();
                    int now = ++on_bus;
                    for (int m = max_on_bus; now > m && !max_on_bus.compare_exchange_weak(m, now);) {}
                    sample[id] = (id + 1) * 10 + c;  // "đọc cảm biến"
                    --on_bus;
                    bus.release();
                    sync.arrive_and_wait();         // chờ mọi cảm biến của chu kỳ này
                }
            });
    }

    for (size_t c = 0; c < cycle_sum.size(); c++) std::printf("chu kỳ %zu: tổng %d\n", c, cycle_sum[c]);
    std::printf("tối đa %d thread trên bus cùng lúc\n", max_on_bus.load());
    // chu kỳ c: 10+c + 20+c + 30+c = 60 + 3c
    bool ok = cycle_sum.size() == CYCLES && max_on_bus <= 2;
    for (int c = 0; c < CYCLES && ok; c++) ok = cycle_sum[c] == 60 + 3 * c;
    return ok ? 0 : 1;
}

6.7 thread_local và dữ liệu riêng của thread

thread_local T x; tạo một bản cho mỗi thread, khởi tạo lần đầu dùng, hủy khi thread kết thúc. Dùng cho buffer định dạng log, bộ sinh số ngẫu nhiên, cache theo thread. Lưu ý: destructor của thread_local chạy khi thread thoát; thread bị detach mà process thoát trước thì destructor không chạy. Mỗi thread tạo mới phải trả chi phí khởi tạo TLS.

6.8 std::async và future

std::async(std::launch::async, f) chạy f trên thread mới và trả std::future; exception từ f được ném lại ở get(). Bẫy: future từ std::async chặn trong destructor cho tới khi tác vụ xong, nên std::async(f); không giữ kết quả thực chất là gọi đồng bộ. Không có thread pool ẩn trên libstdc++: mỗi lần gọi là một pthread_create. Với tác vụ nhỏ lặp lại, dùng thread pool tự viết (M14) hoặc vòng lặp sự kiện.

6.9 Data race và công cụ

  • Data race (hai thread truy cập cùng vị trí nhớ, ít nhất một ghi, không đồng bộ) là undefined behavior, không chỉ "giá trị sai".
  • -fsanitize=thread (TSan) phát hiện race lúc chạy, overhead 5–15 lần; chạy test với TSan trên máy dev x86-64 hoặc ARM64.
  • helgrind/drd của Valgrind cho nền không có TSan.
  • gdb: info threads, thread apply all bt để xem thread nào đang chờ gì khi treo.
Góc EmbeddedBao nhiêu thread cho một daemon embedded?

Mỗi thread tốn stack (RAM thật khi được chạm), một task cho scheduler, và cần đồng bộ. Mẫu phổ biến: một thread vòng lặp sự kiện (epoll) cho mọi I/O, một thread real-time cho vòng điều khiển nếu cần, và một pool nhỏ (1–2 thread) cho việc nặng như nén log hay mã hóa. Đặt stack nhỏ hơn bằng pthread_attr_setstacksize nếu RAM ít (chuẩn C++ không có API này cho std::thread).

Ý chínhÝ chính của chương 6

Tự kiểm traService dùng std::jthread nhưng lúc tắt vẫn treo khoảng 30 giây cho tới khi systemd SIGKILL. Thread đó đang chặn ở read() trên một socket. Vì sao request_stop không đủ, và sửa thế nào?

request_stop chỉ đặt cờ; thread đang chặn trong read không kiểm tra cờ. Đăng ký std::stop_callback gọi ::shutdown(sock, SHUT_RDWR) (làm read trả 0) hoặc ghi vào eventfd mà thread chờ cùng bằng poll/epoll; hoặc dùng timeout cho read (SO_RCVTIMEO) và kiểm tra token mỗi vòng.

Tự kiểm trastd::async(std::launch::async, upload_log, path); được gọi trong vòng lặp chính để "chạy nền". Vì sao vòng lặp vẫn bị chậm?

Không lưu future trả về, nên temporary future bị hủy cuối câu lệnh và destructor của nó chờ upload_log xong. Lời gọi thực chất là đồng bộ. Giữ future (hoặc dùng hàng đợi + worker thread).

Tự kiểm traVì sao std::counting_semaphore không dùng được giữa hai process, dù đặt nó trong shared memory?

Chuẩn không bảo đảm nó hoạt động giữa các không gian địa chỉ (hiện thực có thể dùng futex private, hoặc đặt trạng thái ngoài object). Giữa process dùng sem_open hoặc sem_init với pshared = 1, hay pthread_mutex với PTHREAD_PROCESS_SHARED.

Chương 7 · Proceeding with Inter-Process Communication Đọc kỹ

Chuẩn C++ dừng ở ranh giới process: không có message queue, shared memory hay socket. Chương này là nơi lớp bọc RAII của chương 5 phát huy: mỗi cơ chế IPC của POSIX được bọc thành một kiểu C++ chỉ-move, báo lỗi bằng std::system_error/error_code, nhận thời gian bằng std::chrono, nhận buffer bằng std::span. Cơ chế bên dưới đã giải thích kỹ ở B07 ch 43–61; ở đây tập trung vào cách bọc và lựa chọn.

7.2 Mẫu bọc chung

Mọi handle IPC của POSIX có cùng hình dạng: tạo/mở trả handle, đóng handle, và (với đối tượng có tên) unlink tên. Lớp bọc nên:

  1. Chỉ-move (xóa copy constructor), destructor đóng handle.
  2. Tách đóng handle (mỗi process) khỏi xóa tên (chỉ process "chủ" làm, một lần). Gộp hai việc vào destructor là bug kinh điển: process đầu tiên thoát xóa mất queue của mọi process khác.
  3. Nhận thời gian chờ bằng std::chrono::duration, đổi sang timespec tuyệt đối theo CLOCK_REALTIME (yêu cầu của mq_timedreceive, sem_timedwait).
  4. Nhận và trả dữ liệu bằng std::span<const std::byte> hoặc kiểu trivially copyable.

7.3 POSIX message queue

#include <fcntl.h>
#include <mqueue.h>
#include <unistd.h>
#include <sys/wait.h>
#include <cerrno>
#include <chrono>
#include <cstdio>
#include <cstring>
#include <optional>
#include <string>
#include <system_error>
#include <type_traits>
#include <utility>

using namespace std::chrono_literals;

// Đổi khoảng thời gian tương đối sang mốc tuyệt đối CLOCK_REALTIME mà API POSIX yêu cầu
timespec deadline_after(std::chrono::nanoseconds d)
{
    auto t = std::chrono::system_clock::now() + d;
    auto s = std::chrono::time_point_cast<std::chrono::seconds>(t);
    return {static_cast<time_t>(s.time_since_epoch().count()),
            static_cast<long>(std::chrono::nanoseconds(t - s).count())};
}

template <class Msg>
class MessageQueue {
    static_assert(std::is_trivially_copyable_v<Msg>, "chỉ gửi kiểu copy bằng byte được");
public:
    static MessageQueue create(const std::string &name, long max_msgs) {
        mq_attr a{}; a.mq_maxmsg = max_msgs; a.mq_msgsize = sizeof(Msg);
        return MessageQueue(name, O_CREAT | O_EXCL | O_RDWR, &a);
    }
    static MessageQueue open(const std::string &name) { return MessageQueue(name, O_RDWR, nullptr); }
    static void unlink(const std::string &name) { ::mq_unlink(name.c_str()); }   // chỉ "chủ" gọi

    MessageQueue(MessageQueue &&o) noexcept : mq_(std::exchange(o.mq_, mqd_t(-1))) {}
    MessageQueue(const MessageQueue &) = delete;
    ~MessageQueue() { if (mq_ != mqd_t(-1)) ::mq_close(mq_); }   // đóng handle, KHÔNG xóa tên

    void send(const Msg &m, unsigned prio = 0) {
        while (::mq_send(mq_, reinterpret_cast<const char *>(&m), sizeof m, prio) == -1)
            if (errno != EINTR) throw std::system_error(errno, std::system_category(), "mq_send");
    }
    // nullopt khi hết giờ; ném khi lỗi thật
    std::optional<Msg> receive(std::chrono::nanoseconds timeout, unsigned *prio = nullptr) {
        Msg m; timespec ts = deadline_after(timeout);
        for (;;) {
            ssize_t n = ::mq_timedreceive(mq_, reinterpret_cast<char *>(&m), sizeof m, prio, &ts);
            if (n == static_cast<ssize_t>(sizeof m)) return m;
            if (n == -1 && errno == ETIMEDOUT) return std::nullopt;
            if (n == -1 && errno == EINTR) continue;
            throw std::system_error(n == -1 ? errno : EMSGSIZE, std::system_category(), "mq_receive");
        }
    }
private:
    MessageQueue(const std::string &name, int flags, mq_attr *a) : mq_(::mq_open(name.c_str(), flags | O_CLOEXEC, 0600, a)) {
        if (mq_ == mqd_t(-1)) throw std::system_error(errno, std::system_category(), "mq_open " + name);
    }
    mqd_t mq_;
};

struct Event { int sensor; int value; char tag[8]; };

int main()
{
    const std::string name = "/b05-ev-" + std::to_string(::getpid());
    auto owner = MessageQueue<Event>::create(name, 8);

    pid_t pid = ::fork();
    if (pid == 0) {                                      // process "sensord": chỉ biết tên
        try {
            auto q = MessageQueue<Event>::open(name);
            q.send({1, 2350, "temp"}, 1);
            q.send({2, 61, "hum"}, 1);
            q.send({1, 9000, "ALARM"}, 9);               // priority cao: được nhận trước
        } catch (...) { ::_exit(1); }
        ::_exit(0);
    }
    int st; ::waitpid(pid, &st, 0);

    int got = 0; unsigned prio = 0; bool first_is_alarm = false;
    while (auto e = owner.receive(50ms, &prio)) {
        std::printf("[prio %u] sensor %d = %d (%s)\n", prio, e->sensor, e->value, e->tag);
        if (got++ == 0) first_is_alarm = std::strcmp(e->tag, "ALARM") == 0;
    }
    std::printf("hết giờ sau %d thông điệp\n", got);
    MessageQueue<Event>::unlink(name);
    return got == 3 && first_is_alarm ? 0 : 1;
}

Hai chỗ thường sai khi dùng mq_* trực tiếp mà lớp bọc đã che: buffer nhận phải lớn ít nhất bằng mq_msgsize (ở đây bằng đúng sizeof(Msg) vì queue được tạo với kích thước đó), và timeout là mốc tuyệt đối theo đồng hồ thực nên bị ảnh hưởng khi chỉnh giờ hệ thống (chương 8).

7.4 Semaphore giữa process

C++20 std::counting_semaphore chỉ dùng trong một process (chương 6.6). Giữa process có hai lựa chọn POSIX:

  • Named semaphore: sem_open("/name", O_CREAT, 0600, init); process khác mở bằng tên. Nằm trong /dev/shm/sem.name.
  • Unnamed semaphore trong shared memory: sem_init(&s, /*pshared=*/1, init) với s nằm trong vùng mmap(MAP_SHARED). Gọn hơn khi đằng nào cũng có shared memory.

Bọc tương tự MessageQueue: acquire(), release(), try_acquire_for(duration) dùng sem_timedwait (hoặc sem_clockwait của glibc 2.30 với CLOCK_MONOTONIC, tránh vấn đề chỉnh giờ). Đặt tên phương thức giống std::counting_semaphore để code gọi có thể đổi giữa hai loại dễ dàng.

Cẩn thậnSemaphore không có chủ

Process acquire rồi bị SIGKILL thì semaphore kẹt ở 0 mãi mãi. Dùng semaphore cho báo hiệu (có dữ liệu mới), còn loại trừ giữa process dùng pthread_mutex với PTHREAD_PROCESS_SHARED + PTHREAD_MUTEX_ROBUST, hoặc file lock (tự nhả khi process chết).

7.5 Shared memory với kiểu C++

Shared memory là IPC nhanh nhất vì không copy, nhưng C++ thêm ràng buộc về kiểu:

  • Chỉ đặt kiểu trivially copyable / standard layout: số, mảng cố định, struct đơn giản. Không std::string, std::vector, con trỏ, tham chiếu, virtual (vtable pointer chỉ đúng trong một process).
  • Thay con trỏ bằng offset hoặc chỉ số.
  • Đồng bộ bằng std::atomic<T> lock-free (kiểm tra std::atomic<T>::is_always_lock_free; atomic không lock-free dùng khóa nội bộ không chia sẻ được giữa process), semaphore pshared, hoặc mutex PTHREAD_PROCESS_SHARED.
  • Bắt đầu lifetime đúng cách: process tạo vùng nhớ dùng placement new (chương 4.4); process khác chỉ ánh xạ và dùng.

Ví dụ: lớp SharedObject<T> tạo hoặc mở một object T trong POSIX shared memory. Producer ghi một "frame" và báo bằng semaphore pshared nằm ngay trong struct; số thứ tự frame là std::atomic lock-free.

#include <fcntl.h>
#include <semaphore.h>
#include <sys/mman.h>
#include <sys/wait.h>
#include <unistd.h>
#include <atomic>
#include <cerrno>
#include <cstdio>
#include <new>
#include <string>
#include <system_error>
#include <type_traits>
#include <utility>

[[noreturn]] void throw_errno(const std::string &what) { throw std::system_error(errno, std::system_category(), what); }

template <class T>
class SharedObject {
    static_assert(std::is_standard_layout_v<T>, "không đặt kiểu phức tạp vào shared memory");
public:
    // Process chủ: tạo object mới, chạy constructor của T
    template <class... A> static SharedObject create(const std::string &name, A &&...args) {
        int fd = ::shm_open(name.c_str(), O_CREAT | O_EXCL | O_RDWR | O_CLOEXEC, 0600);
        if (fd == -1) throw_errno("shm_open " + name);
        if (::ftruncate(fd, sizeof(T)) == -1) { ::close(fd); throw_errno("ftruncate"); }
        SharedObject s(fd, true);
        new (s.mem_) T(std::forward<A>(args)...);           // bắt đầu lifetime
        return s;
    }
    // Process khác: chỉ ánh xạ object đã có
    static SharedObject open(const std::string &name) {
        int fd = ::shm_open(name.c_str(), O_RDWR | O_CLOEXEC, 0);
        if (fd == -1) throw_errno("shm_open " + name);
        return SharedObject(fd, false);
    }
    static void unlink(const std::string &name) { ::shm_unlink(name.c_str()); }

    SharedObject(SharedObject &&o) noexcept : mem_(std::exchange(o.mem_, nullptr)), owner_(o.owner_) {}
    SharedObject(const SharedObject &) = delete;
    ~SharedObject() {
        if (!mem_) return;
        if (owner_) get()->~T();                            // chủ kết thúc lifetime
        ::munmap(mem_, sizeof(T));
    }
    T *get() const noexcept { return std::launder(static_cast<T *>(mem_)); }
    T *operator->() const noexcept { return get(); }
private:
    SharedObject(int fd, bool owner) : owner_(owner) {
        mem_ = ::mmap(nullptr, sizeof(T), PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
        int err = errno;
        ::close(fd);                                        // mapping vẫn sống sau khi đóng fd
        if (mem_ == MAP_FAILED) { mem_ = nullptr; errno = err; throw_errno("mmap"); }
    }
    void *mem_ = nullptr;
    bool owner_;
};

struct Frame {
    sem_t ready;                          // producer → consumer: frame đã ghi xong
    sem_t consumed;                       // consumer → producer: đã đọc xong, được ghi đè
    std::atomic<unsigned> seq{0};
    int samples[64];
    Frame() {
        if (::sem_init(&ready, /*pshared=*/1, 0) == -1 || ::sem_init(&consumed, 1, 0) == -1) throw_errno("sem_init");
    }
    ~Frame() { ::sem_destroy(&ready); ::sem_destroy(&consumed); }
};

void wait(sem_t &s) { while (::sem_wait(&s) == -1 && errno == EINTR) {} }
static_assert(std::atomic<unsigned>::is_always_lock_free, "atomic phải lock-free để chia sẻ giữa process");

int main()
{
    const std::string name = "/b05-frame-" + std::to_string(::getpid());
    auto shm = SharedObject<Frame>::create(name);

    pid_t pid = ::fork();
    if (pid == 0) {                                         // consumer
        try {
            auto f = SharedObject<Frame>::open(name);
            long sum = 0;
            for (int k = 0; k < 3; k++) {
                wait(f->ready);
                for (int v : f->samples) sum += v;
                std::printf("consumer: frame seq=%u\n", f->seq.load(std::memory_order_relaxed));
                ::sem_post(&f->consumed);
            }
            std::fflush(stdout);
            ::_exit(sum == 64 * (1 + 2 + 3) ? 0 : 2);
        } catch (...) { ::_exit(1); }
    }

    for (int k = 1; k <= 3; k++) {                          // producer
        for (int &v : shm->samples) v = k;
        shm->seq.store(k, std::memory_order_relaxed);
        ::sem_post(&shm->ready);                            // sem_post/sem_wait đồng bộ hóa bộ nhớ
        wait(shm->consumed);                                // buffer đơn: chờ đọc xong mới ghi đè
    }
    int st; ::waitpid(pid, &st, 0);
    SharedObject<Frame>::unlink(name);
    std::printf("consumer thoát với mã %d\n", WEXITSTATUS(st));
    return WIFEXITED(st) && WEXITSTATUS(st) == 0 ? 0 : 1;
}

Ví dụ dùng buffer đơn với hai semaphore: ready báo có frame, consumed báo đã đọc xong, nên producer không bao giờ ghi đè frame đang được đọc. sem_post/sem_wait cũng là điểm đồng bộ bộ nhớ, nên dữ liệu samples ghi trước sem_post chắc chắn được thấy sau sem_wait. Thiết kế thật thường dùng ring buffer N slot: semaphore free_slots khởi tạo N và filled_slots khởi tạo 0, để producer chạy trước consumer tối đa N frame; hoặc ring buffer lock-free với chỉ số atomic (chương 9.6).

7.6 Socket

Socket là IPC tổng quát nhất: cùng API cho cục bộ (AF_UNIX) và mạng (AF_INET/AF_INET6). Sách trình bày UDP và TCP; mô hình chi tiết (backlog, TIME_WAIT, SO_REUSEADDR, partial I/O, SIGPIPE) xem B07 ch 56–61.

Lớp bọc C++ cho socket thường gồm:

  • Socket sở hữu fd (dựa trên UniqueFd), constructor nhận domain/type và luôn thêm SOCK_CLOEXEC.
  • send(std::span<const std::byte>) / receive(std::span<std::byte>) trả số byte hoặc error_code.
  • Hàm tiện ích send_all lặp tới khi gửi đủ (stream), dùng MSG_NOSIGNAL để không chết vì SIGPIPE.
  • Địa chỉ bọc trong kiểu riêng (Endpoint) dựng từ getaddrinfo, không để code gọi đụng sockaddr.

Ví dụ: UDP "telemetry" trên loopback, dùng std::span cho buffer và std::as_bytes để gửi struct. Datagram giữ ranh giới: mỗi receive nhận đúng một gói.

class UdpSocket {
public:
    UdpSocket() : fd_(::socket(AF_INET, SOCK_DGRAM | SOCK_CLOEXEC, 0)) {
        if (fd_ == -1) throw std::system_error(errno, std::system_category(), "socket");
    }
    UdpSocket(UdpSocket &&o) noexcept : fd_(std::exchange(o.fd_, -1)) {}
    UdpSocket(const UdpSocket &) = delete;
    ~UdpSocket() { if (fd_ != -1) ::close(fd_); }

    // bind loopback, port 0 = kernel chọn; trả về port thật
    uint16_t bind_loopback() {
        sockaddr_in a{}; a.sin_family = AF_INET; a.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
        if (::bind(fd_, reinterpret_cast<sockaddr *>(&a), sizeof a) == -1)
            throw std::system_error(errno, std::system_category(), "bind");
        socklen_t len = sizeof a;
        ::getsockname(fd_, reinterpret_cast<sockaddr *>(&a), &len);
        return ntohs(a.sin_port);
    }
    void set_timeout_ms(int ms) {
        timeval tv{ms / 1000, (ms % 1000) * 1000};
        ::setsockopt(fd_, SOL_SOCKET, SO_RCVTIMEO, &tv, sizeof tv);
    }
    std::error_code send_to(std::span<const std::byte> data, uint16_t port) {
        sockaddr_in a{}; a.sin_family = AF_INET; a.sin_port = htons(port); a.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
        if (::sendto(fd_, data.data(), data.size(), 0, reinterpret_cast<sockaddr *>(&a), sizeof a) == -1)
            return {errno, std::system_category()};
        return {};
    }
    // Trả số byte nhận được; ec = resource_unavailable_try_again khi hết giờ
    size_t receive(std::span<std::byte> buf, std::error_code &ec) {
        ssize_t n = ::recv(fd_, buf.data(), buf.size(), 0);
        if (n == -1) { ec = {errno, std::system_category()}; return 0; }
        ec.clear();
        return static_cast<size_t>(n);
    }
private:
    int fd_;
};

struct Telemetry { uint32_t seq; int16_t temp_c10; uint16_t rssi; };   // 8 byte, không padding

int main()
{
    UdpSocket rx, tx;
    uint16_t port = rx.bind_loopback();
    rx.set_timeout_ms(100);

    for (uint32_t i = 0; i < 3; i++) {
        Telemetry t{i, static_cast<int16_t>(235 + i), 70};
        if (auto ec = tx.send_to(std::as_bytes(std::span(&t, 1)), port)) { std::printf("%s\n", ec.message().c_str()); return 1; }
    }

    int got = 0;
    for (;;) {
        Telemetry t;
        std::error_code ec;
        size_t n = rx.receive(std::as_writable_bytes(std::span(&t, 1)), ec);
        if (ec == std::errc::resource_unavailable_try_again) break;     // SO_RCVTIMEO hết giờ
        if (ec || n != sizeof t) return 1;
        std::printf("seq=%u temp=%.1f rssi=%u\n", t.seq, t.temp_c10 / 10.0, t.rssi);
        got++;
    }
    std::printf("port %u, nhận %d datagram, sau đó hết giờ\n", port, got);
    return got == 3 ? 0 : 1;
}

8.4 Ngủ và vòng lặp định kỳ

  • std::this_thread::sleep_for(d): ngủ ít nhất d (theo steady_clock); thức dậy trễ hơn do lập lịch.
  • std::this_thread::sleep_until(tp): ngủ tới mốc. Với steady_clock libstdc++ dùng clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME).

Vòng lặp định kỳ đúng: tính mốc tiếp theo bằng cộng chu kỳ vào mốc trước, không phải "bây giờ + chu kỳ". Cách thứ hai cộng dồn thời gian xử lý và độ trễ đánh thức, làm chu kỳ trôi.

#include <chrono>
#include <cstdio>
#include <format>
#include <thread>

using namespace std::chrono;
using namespace std::chrono_literals;

void busy_work(milliseconds d) { auto end = steady_clock::now() + d; while (steady_clock::now() < end) {} }

// Chạy n chu kỳ, trả về tổng thời gian thực tế
template <bool Absolute>
milliseconds run(int n, milliseconds period, milliseconds work)
{
    auto start = steady_clock::now();
    auto next = start;
    for (int i = 0; i < n; i++) {
        busy_work(work);
        if constexpr (Absolute) {
            next += period;                          // mốc tuyệt đối: không trôi
            std::this_thread::sleep_until(next);
        } else {
            std::this_thread::sleep_for(period);     // tương đối: trôi thêm "work" mỗi vòng
        }
    }
    return duration_cast<milliseconds>(steady_clock::now() - start);
}

int main()
{
    constexpr int N = 10;
    auto rel = run<false>(N, 20ms, 5ms);
    auto abs = run<true>(N, 20ms, 5ms);
    std::printf("%s\n", std::format("mong đợi {}, sleep_for: {}, sleep_until: {}", N * 20ms, rel, abs).c_str());

    // duration_cast cắt, floor/ceil/round làm tròn có hướng
    std::printf("%s\n", std::format("cast(-1500ms)={} floor={} ceil={} round(2500ms)={}",
        duration_cast<seconds>(-1500ms), floor<seconds>(-1500ms), ceil<seconds>(-1500ms), round<seconds>(2500ms)).c_str());

    auto ymd = 2026y / October / 27d;
    auto next_month_end = year_month_day_last{ymd.year(), month_day_last{ymd.month() + months{1}}};
    std::printf("%s\n", std::format("{} là {:%A}; cuối tháng sau: {}", ymd, weekday{sys_days{ymd}},
                                     year_month_day{next_month_end}).c_str());

    bool ok = abs >= 200ms && abs < 245ms && rel >= 250ms;     // tương đối trôi khoảng N*5ms
    return ok ? 0 : 1;
}

Trên máy tải nặng, vòng sleep_until có thể trễ một chu kỳ, nhưng sẽ bắt kịp ở vòng sau (ngủ ít hơn), nên trung bình vẫn đúng chu kỳ. Nếu trễ quá một chu kỳ, cần chính sách: bỏ qua chu kỳ bị lỡ (next = now + period) hay chạy dồn.

8.5 Timer: thứ C++ còn thiếu

Chuẩn C++ không có timer kiểu "gọi hàm này sau 500 ms" hay "mỗi 10 ms". Ba lựa chọn trên Linux:

Cách Cơ chế Ưu Nhược
Thread + sleep_until như 8.4 thuần C++ một thread mỗi timer, hủy phức tạp
POSIX timer timer_create SIGEV_SIGNAL (gửi signal) hoặc SIGEV_THREAD (glibc tạo thread gọi hàm) chuẩn POSIX signal khó dùng đúng; SIGEV_THREAD tạo thread mỗi lần hết hạn
timerfd (riêng Linux) timer là một fd, đọc ra số lần hết hạn đưa vào epoll cùng mọi I/O, không signal, không thread chỉ Linux

timerfd là lựa chọn mặc định cho daemon Linux. Bọc nó bằng chrono:

#include <poll.h>
#include <sys/timerfd.h>
#include <unistd.h>
#include <cerrno>
#include <chrono>
#include <cstdint>
#include <cstdio>
#include <system_error>
#include <utility>

using namespace std::chrono_literals;

class Timer {
public:
    Timer() : fd_(::timerfd_create(CLOCK_MONOTONIC, TFD_CLOEXEC | TFD_NONBLOCK)) {
        if (fd_ == -1) throw std::system_error(errno, std::system_category(), "timerfd_create");
    }
    Timer(Timer &&o) noexcept : fd_(std::exchange(o.fd_, -1)) {}
    Timer(const Timer &) = delete;
    ~Timer() { if (fd_ != -1) ::close(fd_); }

    // first: lần đầu sau bao lâu; period: 0 = một lần
    void arm(std::chrono::nanoseconds first, std::chrono::nanoseconds period = {}) {
        itimerspec its{to_ts(period), to_ts(first)};
        if (::timerfd_settime(fd_, 0, &its, nullptr) == -1)
            throw std::system_error(errno, std::system_category(), "timerfd_settime");
    }
    void disarm() { arm({}, {}); }
    // Số lần hết hạn từ lần đọc trước (0 nếu chưa); >1 nghĩa là đã lỡ chu kỳ
    std::uint64_t expirations() {
        std::uint64_t n = 0;
        if (::read(fd_, &n, sizeof n) == -1 && errno != EAGAIN)
            throw std::system_error(errno, std::system_category(), "read timerfd");
        return n;
    }
    int fd() const noexcept { return fd_; }   // để đưa vào poll/epoll
private:
    static timespec to_ts(std::chrono::nanoseconds d) {
        auto s = std::chrono::duration_cast<std::chrono::seconds>(d);
        return {static_cast<time_t>(s.count()), static_cast<long>((d - s).count())};
    }
    int fd_;
};

int main()
{
    Timer tick, timeout;
    tick.arm(10ms, 10ms);              // định kỳ 10 ms
    timeout.arm(105ms);                // một lần, sau 105 ms

    pollfd fds[] = {{tick.fd(), POLLIN, 0}, {timeout.fd(), POLLIN, 0}};
    std::uint64_t ticks = 0; bool done = false;
    auto start = std::chrono::steady_clock::now();
    while (!done) {
        if (::poll(fds, 2, 1000) <= 0) return 1;
        if (fds[0].revents & POLLIN) ticks += tick.expirations();
        if (fds[1].revents & POLLIN) done = timeout.expirations() > 0;
    }
    tick.disarm();

    // Mô phỏng vòng lặp bị kẹt: không đọc trong 55 ms, rồi đọc một lần
    tick.arm(10ms, 10ms);
    ::usleep(55 * 1000);
    std::uint64_t missed = tick.expirations();

    auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(std::chrono::steady_clock::now() - start);
    std::printf("tick trong 105 ms: %llu; sau khi kẹt 55 ms đọc được %llu lần hết hạn; tổng %lld ms\n",
                (unsigned long long)ticks, (unsigned long long)missed, (long long)ms.count());
    return ticks >= 9 && ticks <= 11 && missed >= 4 && missed <= 6 ? 0 : 1;
}

Giá trị đọc được lớn hơn 1 là tín hiệu overrun: vòng lặp xử lý chậm hơn chu kỳ. Daemon real-time nên đếm và báo cáo con số này.

8.6 Signal trong chương trình C++

Signal là thông báo bất đồng bộ kernel gửi tới process (B07 ch 20–22). Các signal một service phải quan tâm:

Signal Nguồn Xử lý
SIGTERM systemd stop, kill tắt sạch
SIGINT Ctrl+C tắt sạch
SIGHUP quy ước: đọc lại cấu hình reload
SIGPIPE ghi vào pipe/socket đã đóng bỏ qua, xử lý EPIPE
SIGCHLD con thoát waitpid
SIGSEGV, SIGBUS, SIGABRT lỗi để mặc định (core dump), không cố phục hồi

std::signal của C++ rất hạn chế: chuẩn chỉ cho handler làm việc với volatile std::sig_atomic_t và atomic lock-free. Trong handler không được: cấp phát, dùng std::cout/printf, khóa mutex, ném exception, gọi hầu hết hàm thư viện (chỉ hàm async-signal-safe).

Với chương trình C++ đa luồng, cách sạch nhất không dùng handler:

  1. Ở đầu main, trước khi tạo thread nào, chặn các signal cần xử lý (pthread_sigmask(SIG_BLOCK)). Thread tạo sau thừa kế mask, nên không thread nào bị signal ngắt bất ngờ.
  2. Nhận signal đồng bộ như dữ liệu: signalfd trong vòng epoll, hoặc một thread riêng gọi sigwait.
  3. Chuyển signal thành hành động C++ bình thường: stop_source.request_stop(), đặt cờ reload, đẩy sự kiện vào hàng đợi.
#include <pthread.h>
#include <signal.h>
#include <unistd.h>
#include <atomic>
#include <chrono>
#include <cstdio>
#include <stop_token>
#include <thread>
#include <vector>

using namespace std::chrono_literals;

int main()
{
    // 1. Chặn signal trước khi có thread nào
    sigset_t set;
    sigemptyset(&set);
    sigaddset(&set, SIGTERM); sigaddset(&set, SIGINT); sigaddset(&set, SIGHUP);
    pthread_sigmask(SIG_BLOCK, &set, nullptr);
    ::signal(SIGPIPE, SIG_IGN);

    std::stop_source stop;
    std::atomic<int> reloads{0};
    std::atomic<long> work_done{0};

    // 2. Worker: không lo signal, chỉ theo dõi stop_token
    std::vector<std::jthread> workers;
    for (int i = 0; i < 2; i++)
        workers.emplace_back([&, tok = stop.get_token()] {
            while (!tok.stop_requested()) { work_done++; std::this_thread::sleep_for(1ms); }
        });

    // 3. Thread signal: nhận đồng bộ bằng sigwait, đổi thành hành động C++
    std::jthread sig_thread([&] {
        for (;;) {
            int sig = 0;
            if (sigwait(&set, &sig) != 0) continue;
            if (sig == SIGHUP) { reloads++; std::printf("SIGHUP: đọc lại cấu hình\n"); continue; }
            std::printf("nhận %s: yêu cầu dừng\n", sig == SIGTERM ? "SIGTERM" : "SIGINT");
            stop.request_stop();
            return;
        }
    });

    // Mô phỏng systemd: reload rồi stop
    std::this_thread::sleep_for(20ms);
    ::kill(::getpid(), SIGHUP);
    std::this_thread::sleep_for(20ms);
    ::kill(::getpid(), SIGTERM);

    sig_thread.join();
    workers.clear();                                   // ~jthread join từng worker
    std::printf("đã dừng sạch: %d lần reload, worker chạy %ld vòng\n", reloads.load(), work_done.load());
    return reloads == 1 && stop.stop_requested() && work_done > 0 ? 0 : 1;
}

Với chương trình dùng epoll, thay thread sigwait bằng signalfd(-1, &set, SFD_CLOEXEC) đưa vào vòng lặp (B07 ch 22). Dù dùng cách nào, signal phải được chặn ở mọi thread, nếu không kernel có thể giao nó cho một thread không chặn và handler mặc định (kết thúc process) chạy.

Cẩn thận`sleep_for` và signal

Nếu có handler signal, std::this_thread::sleep_for của libstdc++ tự ngủ tiếp phần còn lại khi bị ngắt, nên không bị rút ngắn. Nhưng các syscall gọi trực tiếp như poll, epoll_wait, select, nanosleep luôn trả EINTR khi handler chạy, kể cả với SA_RESTART; các syscall khác cũng trả EINTR nếu handler cài không có SA_RESTART. Lớp bọc của chương 7 vì vậy luôn lặp lại khi gặp EINTR.

Chương 9 · Understanding the C++ Memory Model Đọc kỹ

Mutex che giấu một sự thật: CPU và compiler sắp xếp lại thao tác bộ nhớ. Trên ARM (hầu hết board embedded Linux), việc sắp xếp lại còn mạnh hơn x86, nên code lock-free "chạy được trên laptop" có thể hỏng trên thiết bị. Chương này giải thích memory model của C++: khi nào một thread chắc chắn thấy dữ liệu thread khác ghi, các memory_order, std::atomic_ref, atomic::wait, và cách áp dụng cho shared memory giữa process. Chi tiết sâu hơn (lock-free stack/queue, ABA, hazard pointer) ở B02 ch 5 và 7.

9.1 Vì sao cần memory model

Ba tầng có thể đổi thứ tự thao tác bộ nhớ:

  1. Compiler: giữ biến trong thanh ghi, đổi chỗ load/store độc lập, gộp hoặc bỏ store thừa.
  2. CPU: thực thi không theo thứ tự, store buffer (store của nhân này chưa hiện ra với nhân khác), load suy đoán.
  3. Hệ thống bộ nhớ: cache của mỗi nhân, coherence protocol.

Trong một thread, mọi sắp xếp lại đều vô hình ("as-if" rule). Giữa các thread, nó lộ ra. Ví dụ kinh điển:

int data = 0; bool ready = false;         // KHÔNG atomic
// thread A                // thread B
data = 42;                 while (!ready) {}      // compiler có thể biến thành vòng lặp vô hạn
ready = true;              use(data);             // có thể thấy data == 0

Đây là data race, nên là undefined behavior. volatile không sửa được: nó chỉ ngăn compiler bỏ truy cập, không ngăn CPU đổi thứ tự và không tạo đồng bộ giữa thread (volatile dành cho thanh ghi phần cứng và sig_atomic_t).

9.2 Các quan hệ cơ bản

  • Memory location: một object kiểu vô hướng, hoặc một dãy bit field liền kề. Hai thread ghi hai char khác nhau trong cùng struct thì không race (nhưng có thể false sharing, 9.7).
  • Sequenced-before: thứ tự trong một thread.
  • Synchronizes-with: một store release trên atomic x và một load acquire trên x đọc được giá trị đó. Các điểm đồng bộ khác: unlock/lock cùng mutex, std::thread constructor (với hàm thread), join, promise::set_value/future::get, sem_post/sem_wait.
  • Happens-before: bắc cầu qua sequenced-before và synchronizes-with. Nếu ghi A happens-before đọc B, B chắc chắn thấy A (hoặc giá trị mới hơn).

Mục tiêu khi viết code đồng thời: mọi truy cập dữ liệu không atomic dùng chung phải có quan hệ happens-before rõ ràng.

int data = 0; std::atomic<bool> ready{false};

9.4 Thao tác atomic hay dùng

std::atomic<int> n{0};
n.fetch_add(1, std::memory_order_relaxed);
int old = n.exchange(5);
int expected = 5;
while (!n.compare_exchange_weak(expected, expected * 2)) {}   // weak có thể thất bại giả: luôn trong vòng lặp
std::atomic<bool>::is_always_lock_free;                      // hằng lúc biên dịch
std::atomic_flag f;  f.test_and_set(); f.clear();            // luôn lock-free

std::atomic<T> với T lớn (struct 16 byte trên ARM32) có thể không lock-free: libatomic dùng bảng khóa nội bộ. Hậu quả: chậm, không async-signal-safe, và không hoạt động giữa process qua shared memory. Luôn static_assert(std::atomic<T>::is_always_lock_free) khi điều đó quan trọng.

9.5 C++20: atomic_ref, wait/notify

  • std::atomic_ref<T> r(x); thao tác atomic trên một object không phải std::atomic: dữ liệu trong buffer có sẵn, struct C, vùng mmap. Trong thời gian có atomic_ref, mọi truy cập tới x phải qua atomic_ref. x phải căn chỉnh theo atomic_ref<T>::required_alignment.
  • a.wait(old): chặn tới khi giá trị khác old (có thể thức dậy giả, nên tự kiểm tra lại). a.notify_one()/notify_all(): đánh thức. Trên Linux libstdc++ dùng futex: không tốn CPU khi chờ, rẻ hơn mutex + condition variable cho cờ đơn giản. std::latch, std::counting_semaphore của libstdc++ xây trên cơ chế này.
#include <atomic>
#include <cstdio>
#include <thread>
#include <vector>

// Một "cổng" một-lần: nhiều thread chờ, một thread mở. Không mutex, không cv.
class Gate {
public:
    void wait() const { while (!open_.load(std::memory_order_acquire)) open_.wait(false, std::memory_order_acquire); }
    void open() { open_.store(true, std::memory_order_release); open_.notify_all(); }
private:
    std::atomic<bool> open_{false};
};

struct Config { int baud = 0; int retries = 0; };   // dữ liệu thường, KHÔNG atomic

int main()
{
    Gate configured;
    Config cfg;                                    // ghi trước open(), đọc sau wait()
    std::atomic<int> seen_ok{0};
    alignas(std::atomic_ref<int>::required_alignment) int raw_counter = 0;   // int thường dùng atomic_ref

    {
        std::vector<std::jthread> ts;
        for (int i = 0; i < 4; i++)
            ts.emplace_back([&] {
                configured.wait();                 // acquire: thấy mọi ghi trước open()
                if (cfg.baud == 115200 && cfg.retries == 3) seen_ok.fetch_add(1, std::memory_order_relaxed);
                std::atomic_ref<int>(raw_counter).fetch_add(1, std::memory_order_relaxed);
            });
        cfg.baud = 115200;                         // chuẩn bị dữ liệu
        cfg.retries = 3;
        configured.open();                         // release: công bố
    }                                              // join: main thấy raw_counter cuối cùng
    std::printf("thread thấy cấu hình đúng: %d/4, raw_counter=%d\n", seen_ok.load(), raw_counter);
    return seen_ok == 4 && raw_counter == 4 ? 0 : 1;
}

9.6 Ví dụ: ring buffer SPSC lock-free

Hàng đợi một producer, một consumer (SPSC) là cấu trúc lock-free hữu ích nhất trong embedded: thread nhận UART đẩy byte, thread xử lý lấy ra; hoặc callback âm thanh/ADC đẩy mẫu cho thread ghi file. Chỉ cần hai chỉ số atomic:

  • Producer ghi dữ liệu vào slot, rồi head.store(..., release).
  • Consumer head.load(acquire) rồi mới đọc slot; sau khi đọc xong tail.store(..., release) để trả slot.
  • Mỗi chỉ số chỉ do một bên ghi, nên không cần CAS.
#include <array>
#include <atomic>
#include <cstddef>
#include <cstdio>
#include <new>
#include <optional>
#include <thread>

template <class T, std::size_t N>
class SpscRing {
    static_assert((N & (N - 1)) == 0, "N phải là lũy thừa của 2 để dùng mặt nạ");
public:
    bool push(const T &v) {                                     // chỉ producer gọi
        auto h = head_.load(std::memory_order_relaxed);         // chỉ mình ghi head: relaxed đủ
        if (h - tail_.load(std::memory_order_acquire) == N) return false;   // đầy
        buf_[h & (N - 1)] = v;
        head_.store(h + 1, std::memory_order_release);          // công bố slot
        return true;
    }
    std::optional<T> pop() {                                    // chỉ consumer gọi
        auto t = tail_.load(std::memory_order_relaxed);
        if (t == head_.load(std::memory_order_acquire)) return std::nullopt;  // rỗng
        T v = buf_[t & (N - 1)];
        tail_.store(t + 1, std::memory_order_release);          // trả slot cho producer
        return v;
    }
private:
    // Tách head và tail ra hai cache line để producer và consumer không giẫm nhau (false sharing)
    alignas(64) std::atomic<std::size_t> head_{0};
    alignas(64) std::atomic<std::size_t> tail_{0};
    std::array<T, N> buf_{};
};

int main()
{
    constexpr int COUNT = 200000;
    SpscRing<int, 1024> ring;
    long long sum = 0; int received = 0; bool in_order = true;

    {
        std::jthread consumer([&] {
            int expect = 0;
            while (received < COUNT) {
                if (auto v = ring.pop()) {
                    in_order &= *v == expect++;
                    sum += *v; received++;
                } else std::this_thread::yield();
            }
        });
        std::jthread producer([&] {
            for (int i = 0; i < COUNT; i++)
                while (!ring.push(i)) std::this_thread::yield();   // đầy: chờ
        });
    }
    std::printf("nhận %d phần tử, đúng thứ tự: %d, tổng %lld\n", received, in_order, sum);
    return received == COUNT && in_order && sum == (long long)COUNT * (COUNT - 1) / 2 ? 0 : 1;
}

Chỉ số tăng mãi (không quay về 0) và dùng & (N - 1) để lấy slot; phép trừ h - tail vẫn đúng khi tràn số nhờ số học không dấu. Với 64 bit, tràn số không xảy ra trong thực tế.

Đặt SpscRing vào shared memory giữa hai process được, với điều kiện T trivially copyable, atomic lock-free, và một process duy nhất khởi tạo (placement new, chương 7.5). Consumer chờ bằng yield ở đây cho đơn giản; thực tế dùng atomic::wait (trong cùng process) hoặc eventfd/futex (giữa process) để không đốt CPU.

9.7 False sharing

Hai biến độc lập nằm trên cùng cache line (64 byte trên hầu hết ARM Cortex-A và x86) mà hai nhân ghi liên tục: cache line bị "ném qua lại" giữa hai nhân, chậm đi hàng chục lần dù không có data race. Sửa bằng alignas(64) như ví dụ trên, hoặc alignas(std::hardware_destructive_interference_size) (C++17; GCC cảnh báo giá trị này có thể khác giữa các bản build cho CPU khác nhau, nên nhiều dự án đặt cứng 64).

9.8 Fence

std::atomic_thread_fence(order) tạo rào chắn không gắn với một biến cụ thể: một fence release trước một store relaxed tương đương store release (về đồng bộ). Dùng khi nhiều store relaxed cần được công bố cùng lúc, hoặc khi đồng bộ qua thao tác không phải C++ atomic. std::atomic_signal_fence chỉ chặn compiler, dùng giữa thread và signal handler trên cùng thread.

9.9 Memory model và hệ thống

  • Shared memory giữa process: memory model của C++ áp dụng như giữa thread, miễn là dùng atomic lock-free. sem_post/sem_wait, pthread_mutex process-shared, và futex cũng tạo đồng bộ.
  • Thanh ghi thiết bị (mmap /dev/mem, UIO): dùng volatile để mỗi truy cập là một lệnh load/store thật, và barrier phù hợp nếu thứ tự giữa các thanh ghi quan trọng (thanh ghi thường ánh xạ dạng device memory, CPU không đổi thứ tự giữa chúng, nhưng thứ tự giữa RAM thường và thiết bị thì cần std::atomic_thread_fence(seq_cst), hoặc dmb/dsb trên ARM).
  • DMA: buffer chung giữa CPU và thiết bị cần thao tác cache (kernel driver lo); user space chỉ thấy qua API của driver (dma-buf, V4L2).
Ý chínhÝ chính của chương 9
  • Compiler và CPU đổi thứ tự truy cập bộ nhớ; data race là UB; volatile không phải đồng bộ.
  • Release store + acquire load đọc được giá trị đó tạo synchronizes-with; mutex, join, future, semaphore cũng vậy.
  • relaxed cho bộ đếm; acquire/release để công bố dữ liệu; seq_cst khi cần thứ tự toàn cục giữa nhiều atomic.
  • Code thiếu acquire/release thường chạy trên x86 và hỏng trên ARM.
  • atomic_ref cho object không phải atomic; atomic::wait/notify là futex, rẻ cho cờ.
  • SPSC ring: hai chỉ số, mỗi bên ghi một chỉ số, acquire/release, tách cache line.
  • Atomic trong shared memory phải is_always_lock_free.
Tự kiểm traCờ dừng bool running = true; được thread chính đặt false, thread worker kiểm tra while (running). Bản build debug dừng được, bản -O2 không bao giờ dừng. Giải thích và sửa.

Không có đồng bộ nên compiler được phép giả định running không đổi trong vòng lặp và nâng phép đọc ra ngoài (vòng lặp vô hạn). Đó là data race, UB. Dùng std::atomic<bool> (relaxed là đủ cho cờ dừng thuần túy, acquire/release nếu cờ còn công bố dữ liệu), hoặc tốt hơn std::jthread + stop_token.

Tự kiểm traTrong SPSC ring buffer, nếu producer dùng head.store(h + 1, memory_order_relaxed) thay vì release, điều gì có thể xảy ra trên ARM?

Store vào buf_[slot] có thể hiện ra với consumer sau store vào head. Consumer thấy head mới, đọc slot và nhận giá trị cũ hoặc nửa vời. Release ngăn các ghi trước nó bị dời xuống sau; acquire ở consumer ngăn đọc slot bị dời lên trước khi đọc head.

Tự kiểm traHai thread mỗi thread tăng bộ đếm riêng của mình (counters[0], counters[1] trong một mảng std::atomic<long>[2]), không chia sẻ gì, nhưng nhanh hơn hẳn khi chạy trên một nhân. Vì sao?

False sharing: hai phần tử nằm chung một cache line, mỗi lần ghi buộc cache line chuyển quyền sở hữu giữa hai nhân. Căn mỗi bộ đếm theo cache line (struct alignas(64) Counter { std::atomic<long> v; };).

10.1 Coroutine là gì

Coroutine là hàm có thể tạm dừng giữa chừng và tiếp tục sau đó, giữ nguyên biến cục bộ. Trong C++20, một hàm là coroutine nếu thân nó chứa co_await, co_yield hoặc co_return.

  • Stackless: trạng thái (biến cục bộ, tham số, điểm dừng) được lưu trong một coroutine frame cấp phát riêng (thường trên heap), không phải một stack riêng. Coroutine chỉ dừng được ở chính thân nó, không dừng từ trong hàm thường mà nó gọi.
  • So với thread: tạm dừng và tiếp tục chỉ là lưu/nạp vài con trỏ (hàng ns), không qua kernel, không cần khóa nếu mọi coroutine chạy trên một thread.
  • So với callback: biến cục bộ sống qua các điểm chờ, try/catch và vòng lặp viết tự nhiên, không phải dựng state machine bằng tay.

Chuẩn C++20 chỉ cung cấp cơ chế (từ khóa, std::coroutine_handle, các concept awaitable); không có kiểu task hay generator sẵn (C++23 thêm std::generator). Ta phải tự viết (hoặc dùng thư viện như cppcoro, libcoro, Boost.Asio, folly).

10.3 Generator: co_yield

Generator sinh dãy giá trị lười: mỗi lần caller xin, coroutine chạy tới co_yield tiếp theo. Ứng dụng embedded tự nhiên: tách khung giao thức từ luồng byte. Ví dụ dưới định nghĩa một Generator<T> tối giản rồi dùng nó để tách khung [0xAA][len][payload...][xor] khỏi dữ liệu có rác và khung hỏng.

#include <coroutine>
#include <cstdint>
#include <cstdio>
#include <exception>
#include <optional>
#include <utility>
#include <vector>

template <class T>
class Generator {
public:
    struct promise_type {
        std::optional<T> current;
        Generator get_return_object() { return Generator{Handle::from_promise(*this)}; }
        std::suspend_always initial_suspend() noexcept { return {}; }   // lười: chưa chạy gì
        std::suspend_always final_suspend() noexcept { return {}; }     // giữ frame để đọc done()
        std::suspend_always yield_value(T v) { current = std::move(v); return {}; }
        void return_void() {}
        void unhandled_exception() { throw; }                           // ném lại cho người gọi next()
    };
    using Handle = std::coroutine_handle<promise_type>;

    explicit Generator(Handle h) : h_(h) {}
    Generator(Generator &&o) noexcept : h_(std::exchange(o.h_, {})) {}
    Generator(const Generator &) = delete;
    ~Generator() { if (h_) h_.destroy(); }                              // RAII cho frame

    std::optional<T> next() {
        if (!h_ || h_.done()) return std::nullopt;
        h_.resume();                                                    // chạy tới co_yield kế tiếp
        if (h_.done()) return std::nullopt;
        return std::move(h_.promise().current);
    }
private:
    Handle h_;
};

using Bytes = std::vector<std::uint8_t>;

// Nhận stream THEO GIÁ TRỊ: frame của coroutine sở hữu dữ liệu, không dangling
Generator<Bytes> frames(Bytes stream, int *bad_checksum)
{
    std::size_t i = 0;
    while (i < stream.size()) {
        if (stream[i] != 0xAA) { i++; continue; }                       // bỏ rác tới byte đồng bộ
        if (i + 2 > stream.size()) break;
        std::size_t len = stream[i + 1];
        if (i + 2 + len + 1 > stream.size()) break;                     // khung chưa đủ
        Bytes payload(stream.begin() + i + 2, stream.begin() + i + 2 + len);
        std::uint8_t x = 0;
        for (auto b : payload) x ^= b;
        if (x == stream[i + 2 + len]) {
            co_yield payload;                                           // dừng ở đây tới lần next()
            i += 3 + len;
        } else {
            ++*bad_checksum;
            i++;                                                        // tìm byte đồng bộ tiếp theo
        }
    }
}

int main()
{
    Bytes rx = {0x00, 0x13,                         // rác
                0xAA, 0x02, 0x10, 0x20, 0x30,       // khung hợp lệ: 10 20, xor = 30
                0xAA, 0x01, 0x55, 0x00,             // sai checksum
                0xFF,
                0xAA, 0x03, 0x01, 0x02, 0x03, 0x00, // khung hợp lệ: 01 02 03, xor = 00
                0xAA, 0x05, 0x01};                  // khung cụt cuối buffer
    int bad = 0, good = 0;
    auto gen = frames(rx, &bad);                    // chưa chạy dòng nào (initial_suspend)
    while (auto f = gen.next()) {
        std::printf("khung %d byte:", (int)f->size());
        for (auto b : *f) std::printf(" %02X", b);
        std::printf("\n");
        good++;
    }
    std::printf("hợp lệ %d, sai checksum %d\n", good, bad);
    return good == 2 && bad == 1 ? 0 : 1;
}

C++23 có std::generator<T> dùng được trong range-for (for (auto &f : frames(rx))); GCC 14 trở lên có sẵn.

10.4 Bẫy vòng đời: tham số tham chiếu

Coroutine thường sống lâu hơn biểu thức gọi nó. Tham số được copy vào frame, nhưng nếu tham số là tham chiếu hay view thì frame chỉ lưu tham chiếu:

Generator<Bytes> frames(const Bytes &stream);   // nguy hiểm
auto g = frames(read_uart());                   // temporary chết cuối dòng này
g.next();                                       // frame đọc stream đã hủy: use-after-free

Quy tắc: tham số của coroutine bất đồng bộ nhận theo giá trị (hoặc shared_ptr). Tương tự, lambda coroutine với capture: capture nằm trong object lambda, không nằm trong frame; nếu lambda là temporary thì capture chết trước coroutine. Dùng hàm tự do với tham số giá trị, hoặc giữ object lambda sống lâu hơn coroutine.

10.5 Cấp phát frame và chi phí

  • Frame mặc định cấp phát bằng operator new. Compiler có thể bỏ cấp phát (HALO, heap allocation elision) khi chứng minh được coroutine không sống lâu hơn caller, nhưng không có bảo đảm; với coroutine bất đồng bộ thực tế hầu như không bao giờ được bỏ.
  • Kiểm soát cấp phát: định nghĩa operator new/operator delete trong promise_type để lấy frame từ memory pool (M06). Nếu operator new có thể thất bại mà không ném (-fno-exceptions), định nghĩa thêm static get_return_object_on_allocation_failure().
  • Kích thước frame phụ thuộc biến cục bộ sống qua điểm dừng; tránh buffer lớn trên "stack" của coroutine.
Góc EmbeddedCoroutine trên thiết bị nhỏ

Coroutine stackless rất hợp với hệ ít RAM: hàng trăm "luồng logic" (mỗi kết nối, mỗi cảm biến) chỉ tốn vài trăm byte frame mỗi cái, so với hàng chục KB stack của mỗi thread. Điều kiện: kiểm soát cấp phát frame (pool) và không chặn trong coroutine (mọi I/O phải qua awaiter non-blocking, nếu không cả vòng sự kiện đứng).

10.6 Awaiter cho I/O: coroutine trên epoll

Ý tưởng: một awaiter readable(fd) khi co_await sẽ đăng ký fd vào epoll kèm handle của coroutine, rồi dừng. Vòng sự kiện epoll_wait, thấy fd sẵn sàng thì resume() đúng coroutine đó. Code trong coroutine trông như I/O chặn, nhưng toàn bộ chạy trên một thread.

#include <fcntl.h>
#include <sys/epoll.h>
#include <sys/timerfd.h>
#include <unistd.h>
#include <cerrno>
#include <chrono>
#include <coroutine>
#include <cstdint>
#include <cstdio>
#include <exception>
#include <stdexcept>
#include <string>
#include <system_error>
#include <utility>
#include <vector>

using namespace std::chrono_literals;

// Task "chạy rồi quên" do vòng sự kiện sở hữu
struct Task {
    struct promise_type {
        Task get_return_object() { return Task{std::coroutine_handle<promise_type>::from_promise(*this)}; }
        std::suspend_always initial_suspend() noexcept { return {}; }   // vòng sự kiện khởi động
        std::suspend_always final_suspend() noexcept { return {}; }     // giữ frame tới khi Task hủy
        void return_void() {}
        void unhandled_exception() { std::terminate(); }
    };
    explicit Task(std::coroutine_handle<promise_type> h) : h(h) {}
    Task(Task &&o) noexcept : h(std::exchange(o.h, {})) {}
    ~Task() { if (h) h.destroy(); }
    std::coroutine_handle<promise_type> h;
};

class EventLoop {
public:
    EventLoop() : ep_(::epoll_create1(EPOLL_CLOEXEC)) {
        if (ep_ == -1) throw std::system_error(errno, std::system_category(), "epoll_create1");
    }
    ~EventLoop() { ::close(ep_); }

    void spawn(Task t) { tasks_.push_back(std::move(t)); }

    // co_await loop.readable(fd): dừng tới khi fd đọc được
    struct Readable {
        EventLoop &loop; int fd; std::coroutine_handle<> waiter;
        bool await_ready() const noexcept { return false; }
        void await_suspend(std::coroutine_handle<> h) {
            waiter = h;
            epoll_event ev{}; ev.events = EPOLLIN; ev.data.ptr = this;   // awaiter sống trong frame khi đang dừng
            if (::epoll_ctl(loop.ep_, EPOLL_CTL_ADD, fd, &ev) == -1)
                throw std::system_error(errno, std::system_category(), "epoll_ctl");
        }
        void await_resume() const noexcept {}
    };
    Readable readable(int fd) { return {*this, fd, {}}; }

    // co_await loop.sleep(d): timerfd một lần, chờ nó đọc được
    struct Sleep {
        Readable r; int tfd;
        bool await_ready() const noexcept { return false; }
        void await_suspend(std::coroutine_handle<> h) { r.await_suspend(h); }
        void await_resume() { std::uint64_t n; ::read(tfd, &n, sizeof n); ::close(tfd); }
    };
    Sleep sleep(std::chrono::nanoseconds d) {
        int tfd = ::timerfd_create(CLOCK_MONOTONIC, TFD_CLOEXEC);
        auto s = std::chrono::duration_cast<std::chrono::seconds>(d);
        itimerspec its{{0, 0}, {static_cast<time_t>(s.count()), static_cast<long>((d - s).count())}};
        ::timerfd_settime(tfd, 0, &its, nullptr);
        return {readable(tfd), tfd};
    }

    void run() {
        for (auto &t : tasks_) t.h.resume();                 // chạy mỗi task tới điểm chờ đầu tiên
        while (pending() > 0) {
            epoll_event evs[16];
            int n = ::epoll_wait(ep_, evs, 16, 2000);
            if (n == -1 && errno == EINTR) continue;
            if (n <= 0) throw std::runtime_error("vòng sự kiện treo");
            for (int i = 0; i < n; i++) {
                auto *r = static_cast<Readable *>(evs[i].data.ptr);
                ::epoll_ctl(ep_, EPOLL_CTL_DEL, r->fd, nullptr);   // một lần: gỡ trước khi resume
                r->waiter.resume();                                // chạy coroutine tới điểm chờ kế tiếp
            }
        }
    }
private:
    int pending() const { int k = 0; for (auto &t : tasks_) k += !t.h.done(); return k; }
    int ep_;
    std::vector<Task> tasks_;
};

// --- Logic ứng dụng: viết tuần tự như code chặn ---

Task producer(EventLoop &loop, int wfd)
{
    for (int i = 0; i < 3; i++) {
        co_await loop.sleep(10ms);
        std::string line = "temp=" + std::to_string(40 + i) + "\n";
        ::write(wfd, line.data(), line.size());
    }
    ::close(wfd);                                            // reader sẽ thấy EOF
}

Task consumer(EventLoop &loop, int rfd, std::vector<std::string> *out)
{
    std::string buf;
    for (;;) {
        co_await loop.readable(rfd);
        char tmp[64];
        ssize_t n = ::read(rfd, tmp, sizeof tmp);
        if (n <= 0) break;                                   // EOF
        buf.append(tmp, n);
        for (std::size_t pos; (pos = buf.find('\n')) != std::string::npos; buf.erase(0, pos + 1))
            out->push_back(buf.substr(0, pos));
    }
    ::close(rfd);
}

Task heartbeat(EventLoop &loop, int *beats)
{
    for (int i = 0; i < 4; i++) { co_await loop.sleep(8ms); ++*beats; }
}

int main()
{
    int p[2];
    ::pipe2(p, O_CLOEXEC | O_NONBLOCK);
    std::vector<std::string> lines; int beats = 0;

    EventLoop loop;
    loop.spawn(consumer(loop, p[0], &lines));
    loop.spawn(producer(loop, p[1]));
    loop.spawn(heartbeat(loop, &beats));
    auto t0 = std::chrono::steady_clock::now();
    loop.run();                                              // một thread, ba "luồng logic"
    auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(std::chrono::steady_clock::now() - t0).count();

    for (auto &l : lines) std::printf("nhận: %s\n", l.c_str());
    std::printf("heartbeat %d lần, tổng %lld ms trên một thread\n", beats, (long long)ms);
    return lines.size() == 3 && lines[2] == "temp=42" && beats == 4 && ms < 100 ? 0 : 1;
}

Những gì ví dụ cố ý đơn giản hóa so với thư viện thật: - Mỗi fd chỉ có một coroutine chờ tại một thời điểm, đăng ký lại mỗi lần co_await (thư viện thật giữ đăng ký và dùng edge-triggered). - Task không trả giá trị và không co_await được lẫn nhau; task lồng nhau cần continuation và symmetric transfer (await_suspend trả về coroutine_handle để tiếp tục coroutine kia ngay, tránh tràn stack khi chuỗi dài). - Không có hủy: thư viện thật kết hợp std::stop_token hoặc "cancellation token" để rút đăng ký epoll và hủy frame an toàn.

10.7 Exception và coroutine

Exception ném ra trong thân coroutine được bắt bởi compiler và chuyển cho promise.unhandled_exception(). Ở đó có thể lưu std::current_exception() để ném lại khi caller lấy kết quả (task trả giá trị), ném lại ngay (generator), hoặc terminate (task chạy-rồi-quên như trên, vì không ai nhận lỗi). Với -fno-exceptions, trả lỗi qua giá trị (co_return std::error_code{...} hoặc expected).

10.8 Khi nào dùng coroutine

Tình huống Gợi ý
Nhiều I/O đồng thời, logic nhiều bước (giao thức hỏi/đáp, retry, timeout) coroutine trên event loop
Tách khung/parse luồng dữ liệu lười generator
Tính toán nặng song song thread / thread pool, không phải coroutine

Tự kiểm traTrong một coroutine chạy trên event loop, bạn gọi std::this_thread::sleep_for(100ms) để chờ thiết bị khởi động. Ảnh hưởng gì?

Lệnh đó chặn cả thread của event loop: mọi coroutine khác (kết nối, heartbeat, watchdog) đứng 100 ms. Phải dùng awaiter không chặn (co_await loop.sleep(100ms) dựa trên timerfd).

Tự kiểm traVì sao final_suspend của Generator trả suspend_always thay vì suspend_never?

Nếu không dừng ở cuối, frame tự hủy khi coroutine chạy xong; handle trong Generator trở thành dangling, và done()/destroy() trong destructor là use-after-free. Dừng ở final suspend giữ frame lại để kiểm tra done() và để kiểu trả về hủy frame một lần duy nhất.
