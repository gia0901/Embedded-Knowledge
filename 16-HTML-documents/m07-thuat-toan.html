Bài 1 · Thao tác bit nâng cao

Module 1 đã có các phép set/clear/toggle/test. Bài này đi tiếp: các mẹo bit được dùng trong driver, giao thức, codec và thư viện toán, cùng các lệnh phần cứng Cortex-M hỗ trợ chúng.

Trích và chèn trường bit

Thanh ghi và gói tin thường chứa nhiều trường (field) nằm cạnh nhau. Hai thao tác cơ bản:

/* Lấy trường rộng `width` bit bắt đầu từ bit `pos` */
static inline uint32_t field_get(uint32_t reg, unsigned pos, unsigned width) {
    return (reg >> pos) & ((1u << width) - 1u);           /* width < 32 */
}
/* Ghi giá trị v vào trường đó, giữ nguyên các bit khác */
static inline uint32_t field_set(uint32_t reg, unsigned pos, unsigned width, uint32_t v) {
    const uint32_t mask = ((1u << width) - 1u) << pos;
    return (reg & ~mask) | ((v << pos) & mask);
}

Cortex-M3 trở lên có lệnh UBFX (unsigned bit field extract), SBFX (signed) và BFI (bit field insert): mỗi thao tác trên là một lệnh. Compiler tự sinh chúng khi pos và width là hằng số.

Trong code thật, nên định nghĩa mask và vị trí bằng hằng số có tên (CMSIS dùng XXX_Pos và XXX_Msk), tránh số ma thuật:

#define ADC_CR_RES_Pos   3u
#define ADC_CR_RES_Msk   (0x3u << ADC_CR_RES_Pos)
ADC1->CR = (ADC1->CR & ~ADC_CR_RES_Msk) | (2u << ADC_CR_RES_Pos);   /* độ phân giải 8 bit */

Mở rộng dấu (sign extension)

Cảm biến thường trả về số có dấu không đủ 8/16/32 bit: ví dụ gia tốc kế 12-bit bù hai, nhiệt độ 13-bit. Phải mở rộng bit dấu lên int16_t/int32_t:

/* x chứa số bù hai `bits` bit ở các bit thấp */
static inline int32_t sign_extend(uint32_t x, unsigned bits) {
    const uint32_t m = 1u << (bits - 1u);                  /* vị trí bit dấu */
    x &= (1u << bits) - 1u;                                /* xóa rác ở bit cao */
    return (int32_t)((x ^ m) - m);
}
/* 12-bit 0xFFF = -1, 0x800 = -2048, 0x7FF = 2047 */

Mẹo (x ^ m) − m: đảo bit dấu rồi trừ trọng số của nó, cho kết quả đúng với cả số dương và âm, không có nhánh, không dựa vào dịch phải số âm (implementation-defined). Cách khác hay gặp là (int32_t)(x << (32 − bits)) >> (32 − bits): ngắn, nhưng dịch trái vào bit dấu rồi dịch phải số âm phụ thuộc compiler (GCC/Clang cho kết quả đúng, và C++20 đã chuẩn hóa dịch phải số học).

Lệnh SBFX làm việc này trong một lệnh.

Đếm bit bằng phần mềm nhanh không cần bảng (SWAR, SIMD within a register):

static inline unsigned popcount32(uint32_t x) {
    x = x - ((x >> 1) & 0x55555555u);                      /* mỗi 2 bit: số bit 1 trong cặp */
    x = (x & 0x33333333u) + ((x >> 2) & 0x33333333u);      /* mỗi 4 bit */
    x = (x + (x >> 4)) & 0x0F0F0F0Fu;                      /* mỗi byte */
    return (x * 0x01010101u) >> 24;                        /* cộng 4 byte vào byte cao */
}

Gray code

Gray code: hai giá trị liên tiếp chỉ khác nhau một bit. Dùng trong encoder quay (rotary encoder), bộ đếm truyền qua clock domain khác nhau (FIFO bất đồng bộ trong FPGA), để tránh đọc sai khi nhiều bit đổi cùng lúc.

static inline uint32_t bin_to_gray(uint32_t b) { return b ^ (b >> 1); }
static inline uint32_t gray_to_bin(uint32_t g) {
    g ^= g >> 16; g ^= g >> 8; g ^= g >> 4; g ^= g >> 2; g ^= g >> 1;
    return g;
}

Bài 2 · Checksum và CRC

Dữ liệu truyền qua dây (UART, RS-485, CAN, SPI), lưu trong Flash hay EEPROM đều có thể bị lỗi bit do nhiễu, mất điện giữa chừng, hay hao mòn bộ nhớ. Mã phát hiện lỗi (error-detecting code) cho phép bên nhận biết dữ liệu có bị thay đổi hay không. Bài này đi từ đơn giản đến CRC, loại được dùng nhiều nhất.

Checksum đơn giản

Tổng byte (sum): cộng mọi byte, lấy 8 hoặc 16 bit thấp. Rất rẻ, nhưng yếu: không phát hiện được đổi thứ tự byte, và hai lỗi bù nhau (một byte +1, byte khác −1) lọt qua.

XOR (LRC trong một số giao thức): XOR mọi byte. Không phát hiện được hai lỗi trên cùng một vị trí bit ở hai byte khác nhau, cũng không phát hiện đổi thứ tự.

Fletcher-16 và Adler-32: dùng hai tổng, tổng thứ hai cộng dồn tổng thứ nhất, nên nhạy với vị trí: phát hiện được đổi thứ tự.

uint16_t fletcher16(const uint8_t *d, size_t n) {
    uint16_t s1 = 0, s2 = 0;
    while (n--) {
        s1 = (uint16_t)((s1 + *d++) % 255u);
        s2 = (uint16_t)((s2 + s1) % 255u);
    }
    return (uint16_t)((s2 << 8) | s1);
}

Fletcher/Adler rẻ hơn CRC phần mềm và tốt hơn tổng thường, nhưng vẫn kém CRC ở khả năng phát hiện lỗi dồn dập (burst error).

Một ví dụ checksum trong giao thức thật là Internet checksum (IP, UDP, TCP): tổng bù một (one's complement) của các từ 16-bit.

CRC: ý tưởng

CRC (Cyclic Redundancy Check) coi dữ liệu là một đa thức với hệ số 0/1 (mỗi bit là một hệ số), rồi chia nó cho một đa thức sinh (generator polynomial) cố định, trong số học modulo 2 (cộng và trừ đều là XOR, không có nhớ). Phần dư của phép chia là giá trị CRC.

Ví dụ nhỏ với đa thức sinh x³ + x + 1 (nhị phân 1011), dữ liệu 1101: thêm 3 bit 0 (bậc của đa thức), rồi chia:

  1100

  ----

Bên nhận chia toàn bộ (dữ liệu + CRC) cho cùng đa thức: phần dư bằng 0 thì không phát hiện lỗi.

Vì sao CRC mạnh? Với đa thức được chọn tốt, CRC n bit chắc chắn phát hiện:

  • Mọi lỗi một bit và hai bit (trong phạm vi độ dài nhất định).
  • Mọi lỗi với số bit lẻ (nếu đa thức có thừa số x + 1).
  • Mọi burst error (chuỗi bit lỗi liên tiếp) dài ≤ n bit.
  • Burst dài hơn: bị lọt với xác suất khoảng 2^−n.

Cài đặt từng bit

Thuật toán MSB-first (refin = false), ví dụ CRC-16/CCITT-FALSE:

uint16_t crc16_ccitt_bitwise(const uint8_t *d, size_t n) {
    uint16_t crc = 0xFFFFu;                              /* init */
    while (n--) {
        crc ^= (uint16_t)(*d++ << 8);                    /* đưa byte vào 8 bit cao */
        for (int b = 0; b < 8; ++b)
            crc = (crc & 0x8000u) ? (uint16_t)((crc << 1) ^ 0x1021u) : (uint16_t)(crc << 1);
    }
    return crc;                                          /* xorout = 0 */
}

Với CRC reflected (refin = refout = true), thay vì đảo bit mỗi byte, ta xử lý theo chiều LSB-first: dịch phải và dùng đa thức đảo bit (0x8005 đảo thành 0xA001, 0x04C11DB7 thành 0xEDB88320):

uint32_t crc32_bitwise(const uint8_t *d, size_t n) {
    uint32_t crc = 0xFFFFFFFFu;
    while (n--) {
        crc ^= *d++;
        for (int b = 0; b < 8; ++b)
            crc = (crc & 1u) ? (crc >> 1) ^ 0xEDB88320u : crc >> 1;
    }
    return crc ^ 0xFFFFFFFFu;                           /* xorout */
}

Cài đặt từng bit nhỏ gọn (vài chục byte code) nhưng chậm: 8 vòng lặp mỗi byte.

Cài đặt bằng bảng

Nhận xét: tác động của 8 bit đi vào lên thanh ghi CRC chỉ phụ thuộc vào 8 bit đó (XOR với 8 bit cao/thấp của thanh ghi). Tính sẵn 256 kết quả vào một bảng, rồi xử lý mỗi byte bằng một lần tra bảng:

static uint32_t k_crc32_table[256];                     /* hoặc const, sinh lúc build */

void crc32_init_table(void) {
    for (uint32_t i = 0; i < 256u; ++i) {
        uint32_t c = i;
        for (int b = 0; b < 8; ++b) c = (c & 1u) ? (c >> 1) ^ 0xEDB88320u : c >> 1;
        k_crc32_table[i] = c;
    }
}

uint32_t crc32_update(uint32_t crc, const uint8_t *d, size_t n) {   /* tính nối tiếp được */
    crc = ~crc;
    while (n--) crc = (crc >> 8) ^ k_crc32_table[(crc ^ *d++) & 0xFFu];
    return ~crc;
}
/* crc32_update(0, "123456789", 9) == 0xCBF43926 */

So sánh các cách:

Bảng 16 phần tử (nibble) 64 byte (CRC-32) ~4×

Trên MCU ít Flash, bảng nibble là thỏa hiệp tốt. Hàm crc32_update nhận giá trị CRC trước đó, nên tính được nối tiếp trên dữ liệu đến từng phần (từng gói, từng block Flash).

CRC phần cứng

Hầu hết MCU hiện đại có khối CRC phần cứng (STM32 CRC unit, nRF, ESP32). STM32F1/F4 chỉ hỗ trợ CRC-32 đa thức Ethernet, xử lý từng word 32-bit, không reflected (khác CRC-32 chuẩn, phải đảo bit dữ liệu và kết quả nếu muốn khớp); STM32 dòng mới hơn (F7, L4, G4, H7…) cho cấu hình đa thức, độ rộng, init và reflection. Dùng khi tính CRC trên khối lớn (kiểm tra image firmware lúc boot), có thể kết hợp DMA để CPU rảnh.

Kiểm tra bằng tính chất "residue"

Một tính chất hữu ích: tính CRC trên (dữ liệu + CRC của nó, ghi đúng thứ tự byte) luôn ra một hằng số cố định (residue; bằng 0 với CRC không có xorout và không reflected). Bên nhận chỉ cần chạy CRC trên cả khung nhận được và so với hằng số đó, không cần tách CRC ra.

Tự kiểm traĐa thức CRC-32 0x04C11DB7 dạng đảo bit là gì, và dùng khi nào?

0xEDB88320; dùng trong cài đặt LSB-first (dịch phải) cho CRC reflected (refin = refout = true).

Bài 3 · Số học fixed-point

Vì sao cần fixed-point

Nhiều MCU không có FPU (Cortex-M0/M0+/M3, nhiều MCU 8/16-bit). Phép tính float khi đó được giả lập bằng phần mềm: một phép nhân float có thể tốn 30 đến 100 chu kỳ, phép chia hàng trăm. Ngay cả trên MCU có FPU (Cortex-M4F/M7), FPU thường chỉ hỗ trợ single precision; dùng double (hằng số 0.5 thay vì 0.5f) lại rơi về phần mềm. Trong ISR, dùng FPU còn làm tăng chi phí lưu ngữ cảnh (lazy stacking).

Fixed-point (dấu phẩy tĩnh) biểu diễn số thực bằng số nguyên với một hệ số tỷ lệ ngầm định là lũy thừa của 2. Mọi phép tính là phép tính số nguyên: nhanh, tất định, kết quả giống hệt nhau trên mọi nền tảng.

Định dạng Q

Ký hiệu Qm.n: m bit phần nguyên (kể cả bit dấu, tùy quy ước), n bit phần thập phân. Giá trị thật = số nguyên / 2^n.

Định dạng Kiểu chứa Khoảng giá trị Độ phân giải
Q15 (Q1.15) int16_t [−1, 1 − 2^−15] 2^−15 ≈ 3,05·10^−5
Q31 (Q1.31) int32_t [−1, 1 − 2^−31] ≈ 4,66·10^−10
Q16.16 int32_t [−32768, 32768) 2^−16 ≈ 1,53·10^−5
Q8.8 int16_t [−128, 128) 1/256

Ví dụ Q16.16: số 3,25 lưu là 3,25 × 65536 = 212992 (0x00034000). Số −0,5 lưu là −32768.

Chọn định dạng theo khoảng giá trị và độ chính xác cần: tín hiệu âm thanh, hệ số bộ lọc trong [−1, 1) dùng Q15/Q31 (định dạng của CMSIS-DSP); giá trị vật lý như nhiệt độ, vị trí dùng Q16.16 hoặc Q với số bit nguyên phù hợp.

Chuyển đổi

typedef int32_t q16_t;                                  /* Q16.16 */
#define Q16_ONE        (1 << 16)
#define Q16_FROM_INT(i)   ((q16_t)((i) * Q16_ONE))
#define Q16_FROM_FLOAT(f) ((q16_t)((f) * Q16_ONE + ((f) >= 0 ? 0.5f : -0.5f)))   /* làm tròn; dùng lúc compile */
static inline int32_t q16_to_int(q16_t x) { return x >> 16; }        /* làm tròn xuống (về −∞) */
static inline float   q16_to_float(q16_t x) { return (float)x / Q16_ONE; }

Hằng số nên được chuyển lúc compile (macro hoặc constexpr), để lúc chạy không có phép tính float nào.

Cộng, trừ

Hai số cùng định dạng cộng trừ trực tiếp như số nguyên. Chỉ cần lo tràn.

Nhân

Nhân hai số Qm.n: tích của hai số nguyên có 2n bit thập phân, phải dịch phải n bit để về lại Qm.n. Tích trung gian cần gấp đôi độ rộng:

static inline q16_t q16_mul(q16_t a, q16_t b) {
    int64_t p = (int64_t)a * b;                         /* 64-bit: Q32.32 */
    p += (int64_t)1 << 15;                              /* làm tròn tới gần nhất */
    return (q16_t)(p >> 16);
}

Cortex-M3+ có lệnh SMULL (nhân 32×32 → 64) chạy trong vài chu kỳ (một chu kỳ trên M4), nên phép nhân này rẻ.

Với Q15 (dùng nhiều trong DSP):

typedef int16_t q15_t;
static inline q15_t q15_mul(q15_t a, q15_t b) {
    int32_t p = (int32_t)a * b;                         /* Q2.30 */
    p = (p + (1 << 14)) >> 15;                          /* về Q1.15, làm tròn */
    if (p > INT16_MAX) p = INT16_MAX;                   /* bão hòa: chỉ xảy ra khi (−1) × (−1) */
    return (q15_t)p;
}

Trường hợp đặc biệt: (−1) × (−1) = +1, nhưng Q15 không biểu diễn được +1 (tối đa 1 − 2^−15). Phải bão hòa (saturate). Cortex-M4 có lệnh SSAT và các lệnh DSP như SMLABB, QADD làm bão hòa trong phần cứng.

Chia

Chia Qm.n cho Qm.n: dịch số bị chia trái n bit trước (để giữ độ chính xác), rồi chia:

static inline q16_t q16_div(q16_t a, q16_t b) {
    return (q16_t)(((int64_t)a << 16) / b);             /* b ≠ 0 */
}

Phép chia chậm (Cortex-M3/M4 có SDIV 2–12 chu kỳ; M0 không có lệnh chia). Mẹo phổ biến: thay chia bằng nhân với nghịch đảo đã tính sẵn (khi số chia là hằng hoặc thay đổi chậm).

Tràn và bão hòa

Trong số học nguyên thông thường, tràn quay vòng: 32767 + 1 = −32768. Với tín hiệu (âm thanh, đầu ra điều khiển), quay vòng là thảm họa: một tín hiệu dương lớn đột ngột thành âm lớn. Số học bão hòa (saturating arithmetic) kẹp kết quả ở giá trị lớn nhất/nhỏ nhất:

static inline int32_t sat_add32(int32_t a, int32_t b) {
    int32_t r;
    if (__builtin_add_overflow(a, b, &r))               /* GCC/Clang: phát hiện tràn có dấu an toàn */
        return (a > 0) ? INT32_MAX : INT32_MIN;
    return r;
}

(Không viết if (a + b > INT32_MAX) vì tràn có dấu là UB, compiler có thể xóa phép kiểm tra. Xem Module 1.)

Ví dụ: bộ điều khiển PI bằng fixed-point

typedef struct { q16_t kp, ki; q16_t integ; q16_t out_min, out_max; } pi_q16_t;

q16_t pi_step(pi_q16_t *c, q16_t setpoint, q16_t measured) {
    q16_t err = setpoint - measured;
    c->integ += q16_mul(c->ki, err);
    if (c->integ > c->out_max) c->integ = c->out_max;   /* anti-windup: kẹp tích phân */
    if (c->integ < c->out_min) c->integ = c->out_min;
    q16_t out = q16_mul(c->kp, err) + c->integ;
    if (out > c->out_max) out = c->out_max;
    if (out < c->out_min) out = c->out_min;
    return out;
}

Mọi phép tính là số nguyên, thời gian thực thi cố định, chạy được trong ISR trên Cortex-M0.

MẹoKhi nào vẫn nên dùng float

Có FPU single precision (M4F, M7) và không quá eo hẹp về thời gian: float cho code dễ đọc hơn nhiều, ít lỗi tràn hơn. Fixed-point vẫn có lợi khi cần kết quả giống hệt từng bit giữa các nền tảng (ví dụ firmware và mô phỏng trên PC), khi không có FPU, hoặc khi dùng lệnh SIMD 16-bit của M4 (xử lý hai mẫu Q15 một lệnh). Luôn viết hằng số float với hậu tố f và bật -Wdouble-promotion.

Ý chínhÝ chính của Bài 3
  • Fixed-point: số nguyên với hệ số tỷ lệ 2^n ngầm định; nhanh và tất định khi không có FPU.
  • Qm.n: chọn theo khoảng giá trị và độ phân giải. Q15/Q31 cho DSP, Q16.16 cho đại lượng vật lý.
  • Nhân: dùng tích gấp đôi độ rộng, dịch phải n bit, làm tròn. Chia: dịch trái số bị chia trước.
  • Bão hòa thay vì quay vòng; Q15 cần xử lý (−1)×(−1). Dùng __builtin_add_overflow, không kiểm tra tràn bằng phép tính có thể tràn.

Q8.8: 1,75 × 256 = 448 (0x01C0). Q16.16: 1,75 × 65536 = 114688 (0x0001C000).

Tự kiểm traNhân hai số Q16.16 mà dùng `int32_t` cho tích trung gian thì sao?

Tích của hai số có 32 bit thập phân và cần tới 64 bit; tính trong 32-bit sẽ tràn (UB với số có dấu) và mất phần nguyên. Phải ép sang int64_t trước khi nhân.

Bài 4 · Lọc tín hiệu, chống dội phím, hysteresis

Dữ liệu từ thế giới thật luôn có nhiễu: ADC dao động vài LSB, nút bấm cơ khí dội (bounce) hàng chục lần khi nhấn, cảm biến nhiệt bị nhiễu điện từ. Firmware cần các bộ lọc đơn giản, rẻ, tất định. Bài này trình bày những bộ lọc được dùng nhiều nhất.

Trung bình trượt (moving average)

Lấy trung bình N mẫu gần nhất. Cài đặt ngây thơ cộng lại N mẫu mỗi lần: O(N). Cài đặt đúng giữ một tổng chạy (running sum) và một ring buffer N mẫu: mỗi mẫu mới thì cộng mẫu mới, trừ mẫu cũ nhất: O(1).

#define MA_N 16u                                        /* lũy thừa 2 để chia bằng dịch bit */

typedef struct { uint16_t buf[MA_N]; uint32_t sum; uint8_t idx; } movavg_t;

uint16_t movavg_update(movavg_t *f, uint16_t x) {
    f->sum += x;
    f->sum -= f->buf[f->idx];                           /* trừ mẫu cũ nhất */
    f->buf[f->idx] = x;
    f->idx = (uint8_t)((f->idx + 1u) & (MA_N - 1u));
    return (uint16_t)((f->sum + MA_N / 2u) >> 4);       /* chia 16, làm tròn */
}

Đặc điểm: giảm nhiễu ngẫu nhiên theo tỷ lệ khoảng √N; phản hồi bước nhảy mất N mẫu để theo kịp hoàn toàn; tốn N ô nhớ. sum phải đủ rộng: 16 mẫu 16-bit cần 20 bit, dùng uint32_t. Khi khởi động, buffer chứa 0 nên đầu ra tăng dần; có thể khởi tạo bằng mẫu đầu tiên (đặt mọi ô và sum = N × x0).

Lọc thông thấp bậc 1 (EMA, IIR)

Exponential moving average (trung bình trượt hàm mũ), còn gọi là bộ lọc IIR bậc 1:

y[n] = y[n−1] + α · (x[n] − y[n−1]),   0 < α ≤ 1

α nhỏ thì lọc mạnh (mượt, chậm), α lớn thì phản ứng nhanh. Ưu điểm lớn: chỉ cần một biến trạng thái, không cần buffer.

Chọn α = 1/2^k để phép nhân thành dịch bit. Nhưng nếu lưu y với cùng độ phân giải như x, phép dịch làm mất các bit thấp và bộ lọc bị kẹt cách giá trị thật vài LSB (khi x − y < 2^k, cập nhật bằng 0). Cách đúng: lưu trạng thái với k bit thập phân thêm (fixed-point):

typedef struct { int32_t acc; } ema_t;                  /* acc = y · 2^K */
#define EMA_K 4                                         /* α = 1/16 */

void ema_init(ema_t *f, int32_t x0) { f->acc = x0 << EMA_K; }

int32_t ema_update(ema_t *f, int32_t x) {
    f->acc += x - (f->acc >> EMA_K);                    /* acc += x − y */
    return (f->acc + (1 << (EMA_K - 1))) >> EMA_K;      /* y làm tròn */
}

Liên hệ với tần số: với tần số lấy mẫu fs và hằng số thời gian τ, α ≈ 1 − e^(−1/(fs·τ)) ≈ 1/(fs·τ) khi fs·τ lớn. Ví dụ lấy mẫu 1 kHz, muốn τ ≈ 16 ms: α ≈ 1/16, tức k = 4.

Bộ lọc trung vị (median)

Trung bình kém với nhiễu xung (spike): một mẫu sai lớn làm lệch kết quả. Median (giá trị giữa sau khi sắp xếp) loại bỏ hẳn spike. Với cửa sổ nhỏ (3 hoặc 5), tìm trung vị bằng vài phép so sánh:

static inline int16_t median3(int16_t a, int16_t b, int16_t c) {
    if (a > b) { int16_t t = a; a = b; b = t; }        /* a ≤ b */
    if (b > c) { b = c; }                               /* b = min(b, c) */
    return (a > b) ? a : b;                             /* max(a, min(b, c)) */
}

Thực tế hay dùng median rồi mới trung bình: median 3 hoặc 5 để cắt spike, sau đó EMA để mượt.

Chống dội phím (debounce)

Nút bấm cơ khí khi đóng hoặc mở dội nhiều lần trong khoảng 1 đến 20 ms (tùy loại nút). Đọc thẳng chân GPIO sẽ thấy hàng chục lần nhấn.

 Mức thật:  ‾‾‾‾‾‾‾‾|________________________
 Đọc được:  ‾‾‾‾‾‾‾‾|_|‾|__|‾|_______________     dội trong vài ms

Cách 1: đếm (integrator). Lấy mẫu định kỳ (ví dụ mỗi 5 ms trong timer tick). Một bộ đếm tăng khi đọc mức 1, giảm khi đọc mức 0, kẹp trong [0, MAX]. Trạng thái chỉ đổi khi bộ đếm chạm 0 hoặc MAX:

#define DB_MAX 4u                                       /* 4 mẫu × 5 ms = 20 ms */
typedef struct { uint8_t count; bool state; } debounce_t;

bool debounce_update(debounce_t *d, bool raw) {         /* gọi mỗi 5 ms */
    if (raw) { if (d->count < DB_MAX) d->count++; }
    else     { if (d->count > 0)      d->count--; }
    if (d->count == DB_MAX) d->state = true;
    else if (d->count == 0) d->state = false;
    return d->state;
}

Cách 2: thanh ghi dịch. Dịch mẫu mới vào một byte; chỉ coi là "đã nhấn" khi toàn bộ byte là 0 (8 mẫu liên tiếp ổn định). Rất gọn, xử lý được 8 nút cùng lúc nếu dùng mỗi bit một nút (dữ liệu "dọc").

uint8_t g_hist;                                         /* 8 mẫu gần nhất của một nút (active low) */
bool button_pressed(bool raw_low) {
    g_hist = (uint8_t)((g_hist << 1) | (raw_low ? 0u : 1u));
    return g_hist == 0x00u;                             /* 8 mẫu liên tiếp đều mức thấp */
}

Phát hiện sự kiện "vừa nhấn" (cạnh) bằng cách so trạng thái đã lọc với lần trước: pressed_event = state && !prev_state.

Không nên debounce bằng ngắt cạnh + delay trong ISR: mỗi lần dội sinh một ngắt (có thể hàng chục ngắt), và delay trong ISR làm hỏng thời gian thực của cả hệ thống. Nếu dùng ngắt để đánh thức MCU khỏi sleep, hãy tắt ngắt chân đó sau lần đầu rồi chuyển sang lấy mẫu định kỳ.

Hysteresis

Khi so sánh tín hiệu nhiễu với một ngưỡng (bật quạt khi nhiệt độ > 40 °C), giá trị dao động quanh ngưỡng làm đầu ra bật tắt liên tục (chattering). Giải pháp: hai ngưỡng khác nhau cho chiều lên và chiều xuống, như Schmitt trigger:

bool fan_control(bool on, int16_t temp_c10) {          /* nhiệt độ × 10 */
    if (!on && temp_c10 >= 400) return true;            /* bật khi ≥ 40,0 °C */
    if ( on && temp_c10 <= 370) return false;           /* tắt khi ≤ 37,0 °C */
    return on;                                          /* trong vùng 37–40: giữ nguyên */
}

Độ rộng vùng hysteresis (ở đây 3 °C) phải lớn hơn biên độ nhiễu. Hysteresis cũng dùng cho cảnh báo pin yếu, ngưỡng mức chất lỏng, phát hiện tín hiệu.

Ý chínhÝ chính của Bài 4
  • Moving average: tổng chạy + ring buffer, O(1); N lũy thừa 2 để chia bằng dịch bit.
  • EMA/IIR bậc 1: một biến trạng thái; lưu trạng thái với bit thập phân thêm để không bị kẹt.
  • Median 3/5 loại spike; thường dùng median rồi EMA.
  • Debounce bằng lấy mẫu định kỳ (integrator hoặc thanh ghi dịch), không delay trong ISR.
  • Hysteresis: hai ngưỡng để tránh chattering quanh ngưỡng.
Tự kiểm traVì sao EMA viết `y += (x − y) >> 4` với `y` cùng độ phân giải với `x` có thể không bao giờ đạt tới giá trị thật?

Khi |x − y| < 16, (x − y) >> 4 bằng 0 (hoặc −1 với số âm), nên y dừng cách x tới 15 LSB. Phải lưu trạng thái với 4 bit thập phân thêm.

Tự kiểm traNút có thời gian dội tối đa 15 ms. Thiết kế debounce bằng bộ đếm với tick 5 ms thế nào?

DB_MAX = 4 (20 ms > 15 ms): trạng thái chỉ đổi sau 4 mẫu liên tiếp nhất quán.

Bài 5 · Thời gian, tick và software timer

Bộ đếm tick và tràn số

Firmware thường có một bộ đếm thời gian tăng đều: SysTick đếm mili giây (HAL_GetTick(), xTaskGetTickCount()), hoặc bộ đếm chu kỳ CPU. Bộ đếm 32-bit mili giây tràn sau 2^32 ms ≈ 49,7 ngày. Thiết bị chạy liên tục sẽ gặp điều này.

Code sai kinh điển:

uint32_t deadline = now() + 500u;
while (now() < deadline) { }        /* SAI khi deadline tràn về số nhỏ: vòng lặp thoát ngay */

Nếu now() = 0xFFFFFF00, deadline tràn thành 0x000000F4, và now() < deadline sai ngay lập tức.

Cách đúng: so sánh hiệu, nhờ số học không dấu quay vòng (Module 1):

uint32_t start = now();
while ((uint32_t)(now() - start) < 500u) { }    /* đúng cả khi bộ đếm tràn */

/* Kiểm tra đã quá hạn: dùng hiệu có dấu */
static inline bool time_after_eq(uint32_t a, uint32_t b) { return (int32_t)(a - b) >= 0; }
if (time_after_eq(now(), deadline)) { /* hết hạn */ }

now() − start cho đúng thời gian trôi qua miễn là nhỏ hơn 2^32 ms. (int32_t)(a − b) >= 0 cho đúng thứ tự giữa hai thời điểm cách nhau dưới 2^31 ms (khoảng 24,8 ngày). Linux kernel có đúng các macro này: time_after(a, b), time_before, time_after_eq cho biến jiffies.

Cẩn thậnBộ đếm 16-bit

Timer phần cứng 16-bit tràn sau 65536 tick (ví dụ 65,5 ms ở 1 MHz). Phép trừ phải được ép về uint16_t: (uint16_t)(now16 − start16). Nếu không, integer promotion lên int (Module 1) làm phép trừ cho số âm thay vì quay vòng.

Software timer: nhu cầu

Phần cứng có ít timer, nhưng firmware cần hàng chục "hẹn giờ": timeout giao tiếp, nháy LED, đọc cảm biến định kỳ, retry, watchdog phần mềm. Software timer dùng một nguồn tick duy nhất để quản lý nhiều timer. Thao tác cần hỗ trợ: start (đặt hẹn), stop (hủy), và tick (mỗi nhịp, tìm và gọi các timer đã hết hạn).

Cách 1: mảng, duyệt mỗi tick

Mỗi timer lưu thời điểm hết hạn; mỗi tick duyệt toàn bộ. Start/stop O(1), tick O(n). Với n ≤ 16 và tick 1 ms, hoàn toàn chấp nhận được và đơn giản nhất.

Cách 2: danh sách sắp xếp hoặc delta list

Danh sách sắp xếp theo thời điểm hết hạn (Module 6, Bài 3): tick chỉ kiểm tra phần tử đầu, O(1); start O(n) để chèn đúng chỗ.

Delta list: mỗi node lưu khoảng cách tới node trước (thay vì thời điểm tuyệt đối). Mỗi tick chỉ cần giảm node đầu một đơn vị; khi về 0 thì nó hết hạn (và các node tiếp theo có delta 0 cũng hết hạn). Không bao giờ phải so sánh với bộ đếm toàn cục, nên không có vấn đề tràn số.

 Timer hết hạn tại t = 5, 8, 8, 15:
 Delta list:  [5] → [3] → [0] → [7]
 Mỗi tick giảm node đầu; khi node đầu = 0, chạy nó và các node 0 kế tiếp.

Cách 3: timer wheel (bánh xe thời gian)

Khi có rất nhiều timer (hàng nghìn, như TCP stack quản lý timeout cho mỗi kết nối), cần start, stop và tick đều O(1). Hashed timing wheel (Varghese và Lauck, 1987):

  • Một mảng N slot, mỗi slot là một danh sách (intrusive) các timer.
  • Một con trỏ cur chỉ slot hiện tại, tăng 1 mỗi tick (quay vòng).
  • Start timer hết hạn sau d tick: đặt vào slot (cur + d) % N, kèm số vòng còn lại d / N.
  • Mỗi tick: tăng cur, duyệt danh sách của slot cur; timer có số vòng 0 thì hết hạn, ngược lại giảm số vòng.
            slot:   0    1    2    3    4    5    6    7
                   [ ]  [A]  [ ]  [B,C] [ ]  [ ]  [D]  [ ]
                         ↑
                        cur     mỗi tick quay sang phải một slot

Start và stop O(1) (chèn/xóa khỏi danh sách đôi). Tick O(1) trung bình (chỉ duyệt một slot). Nếu đa số timer ngắn hơn N tick, gần như không có số vòng phải giảm.

Hierarchical timing wheel: nhiều bánh xe với độ phân giải khác nhau, giống kim giây, phút, giờ của đồng hồ. Bánh tinh (ví dụ 256 slot × 1 ms) và bánh thô (64 slot × 256 ms); timer xa nằm ở bánh thô, khi tới gần thì được chuyển (cascade) xuống bánh tinh. Phủ được khoảng thời gian rất dài với ít slot. Linux kernel dùng timer wheel nhiều tầng cho timer thông thường (từ 4.8 bỏ cascade, chấp nhận giảm độ chính xác với timer dài vì đa số timeout bị hủy trước khi hết hạn), và red-black tree cho hrtimer cần độ chính xác cao.

Callback chạy ở đâu?

Câu hỏi thiết kế quan trọng: callback của timer chạy trong ISR tick hay trong task?

  • Trong ISR: chính xác về thời gian, nhưng callback phải rất ngắn, không chặn, không gọi API không an toàn với ISR.
  • Trong task (ví dụ FreeRTOS timer service task, Linux softirq/workqueue): callback được làm nhiều việc hơn, nhưng có độ trễ phụ thuộc lịch chạy.

FreeRTOS: mọi software timer chạy callback trong daemon task (timer service task); callback không được chặn lâu vì nó làm trễ mọi timer khác.

Ý chínhÝ chính của Bài 5

  • Bộ đếm 16-bit: ép kết quả phép trừ về uint16_t.
  • Software timer: mảng (n nhỏ), danh sách sắp xếp hoặc delta list, timer wheel (n lớn, O(1)), wheel nhiều tầng cho khoảng dài.

Bài 6 · Tìm kiếm, sắp xếp, nội suy và số học nguyên nhanh

Binary search đúng

Binary search trên mảng sắp xếp là O(log n), nhưng nổi tiếng khó viết đúng. Hai lỗi kinh điển:

  • mid = (lo + hi) / 2 tràn khi lo + hi vượt giới hạn kiểu. Viết mid = lo + (hi − lo) / 2.
  • Điều kiện dừng và cập nhật biên lệch nhau một đơn vị, gây lặp vô hạn hoặc bỏ sót.

Mẫu an toàn nhất là lower bound với khoảng nửa mở [lo, hi): tìm vị trí phần tử đầu tiên ≥ key.

size_t lower_bound_u16(const uint16_t *a, size_t n, uint16_t key) {
    size_t lo = 0, hi = n;                              /* [lo, hi) */
    while (lo < hi) {
        size_t mid = lo + (hi - lo) / 2u;
        if (a[mid] < key) lo = mid + 1u; else hi = mid;
    }
    return lo;                                          /* n nếu mọi phần tử < key */
}

C++ có sẵn std::lower_bound, std::upper_bound, std::binary_search, dùng được trên std::array và mảng thường.

Sắp xếp trong firmware

Ít khi cần sắp xếp lượng dữ liệu lớn trên MCU. Khi cần:

  • n nhỏ (dưới khoảng 20–30): insertion sort. Đơn giản, ổn định, tại chỗ, không đệ quy, rất nhanh với n nhỏ và với dữ liệu gần như đã sắp xếp (thêm một mẫu mới vào cửa sổ đã sắp xếp).
  • n lớn: heapsort (O(n log n) xấu nhất, tại chỗ, không đệ quy) hoặc std::sort (introsort: quicksort chuyển sang heapsort khi đệ quy quá sâu).
  • Tránh quicksort đệ quy tự viết trên MCU: xấu nhất O(n²) và độ sâu đệ quy O(n) có thể tràn stack nhỏ.
  • qsort của thư viện C gọi hàm so sánh qua con trỏ mỗi lần, chậm hơn nhiều so với std::sort (inline được).
void insertion_sort_i16(int16_t *a, size_t n) {
    for (size_t i = 1; i < n; ++i) {
        int16_t x = a[i];
        size_t j = i;
        while (j > 0 && a[j - 1u] > x) { a[j] = a[j - 1u]; --j; }
        a[j] = x;
    }
}

Nội suy tuyến tính trên bảng hiệu chuẩn

Cảm biến phi tuyến (NTC thermistor, cảm biến áp suất, cặp nhiệt điện) thường được hiệu chuẩn bằng một bảng các điểm mẫu (x, y). Với x bất kỳ: tìm đoạn chứa x (binary search), rồi nội suy tuyến tính giữa hai điểm hai đầu đoạn:

 y = y0 + (x − x0) · (y1 − y0) / (x1 − x0)

typedef struct { int16_t x; int16_t y; } cal_point_t;

/* Bảng NTC: ADC raw → nhiệt độ × 10 (°C). x tăng dần. */
static const cal_point_t k_ntc[] = {
    { 200, 1250 }, { 450, 900 }, { 900, 600 }, { 1600, 350 },
    { 2400, 180 }, { 3200, 20 }, { 3800, -150 },
};
#define NTC_N (sizeof k_ntc / sizeof k_ntc[0])

int16_t ntc_lookup(int16_t adc) {
    if (adc <= k_ntc[0].x) return k_ntc[0].y;                    /* kẹp hai đầu */
    if (adc >= k_ntc[NTC_N - 1u].x) return k_ntc[NTC_N - 1u].y;
    size_t i = 1;
    while (k_ntc[i].x < adc) ++i;                                 /* n nhỏ: tuyến tính; lớn: binary search */
    const cal_point_t *p0 = &k_ntc[i - 1u], *p1 = &k_ntc[i];
    int32_t num = (int32_t)(adc - p0->x) * (p1->y - p0->y);
    return (int16_t)(p0->y + num / (p1->x - p0->x));
}

Nếu các điểm x cách đều nhau với khoảng là lũy thừa 2, chỉ số đoạn và phép chia đều thành dịch bit: i = adc >> 7, frac = adc & 127, y = y[i] + ((y[i+1] − y[i]) * frac >> 7). Không cần tìm kiếm, không cần phép chia.

Số học nguyên nhanh

Chia cho hằng số: compiler tự thay phép chia cho hằng bằng nhân với "nghịch đảo ma thuật" rồi dịch (vì nhân rẻ hơn chia nhiều, và Cortex-M0 không có lệnh chia). Ví dụ x / 10 với uint32_t:

/* compiler sinh ra tương đương: */
uint32_t div10(uint32_t x) { return (uint32_t)(((uint64_t)x * 0xCCCCCCCDu) >> 35); }

Bài học: viết x / 10, để compiler lo. Chỉ tự làm khi số chia là biến nhưng thay đổi hiếm (tính sẵn nghịch đảo).

Căn bậc hai nguyên (ví dụ tính độ lớn vector gia tốc, RMS) không cần FPU:

uint32_t isqrt32(uint32_t n) {                          /* phần nguyên của √n */
    uint32_t root = 0, bit = 1u << 30;                  /* lũy thừa 4 lớn nhất ≤ 2^32 */
    while (bit > n) bit >>= 2;
    while (bit) {
        if (n >= root + bit) { n -= root + bit; root = (root >> 1) + bit; }
        else root >>= 1;
        bit >>= 2;
    }
    return root;
}

Mỗi vòng xác định một bit của kết quả: 16 vòng cố định, thời gian tất định.

Xấp xỉ độ lớn vector không cần căn: |v| ≈ max + min/2 (sai số tối đa ~12%), hoặc max·15/16 + min·15/32 (sai số ~6%), đủ cho nhiều ứng dụng so ngưỡng. Còn tốt hơn: so sánh bình phương độ lớn với bình phương ngưỡng, không cần căn bậc hai.

Ý chínhÝ chính của Bài 6

  • Sắp xếp: insertion sort cho n nhỏ; tránh quicksort đệ quy tự viết; std::sort > qsort.
  • Hiệu chuẩn phi tuyến: bảng điểm mẫu + nội suy tuyến tính; điểm cách đều 2^k thì không cần chia.
  • Để compiler tối ưu chia cho hằng số; căn nguyên bằng thuật toán bit; so sánh bình phương thay cho căn.

Bài 7 · Tính tất định, WCET và đo hiệu năng

Hệ thống realtime cần gì

Hệ thống realtime không có nghĩa là "nhanh", mà là đúng hạn: kết quả phải có trước deadline. Hard realtime: trễ hạn là lỗi hệ thống (túi khí, điều khiển động cơ, ABS). Soft realtime: trễ hạn làm giảm chất lượng (âm thanh bị vấp, hình giật).

Vì vậy điều quan trọng là WCET (worst-case execution time) của mỗi đoạn code trên đường thời gian thực, và tổng thời gian trong một chu kỳ phải vừa với ngân sách thời gian (time budget).

Đo thời gian thực thi

Bộ đếm chu kỳ DWT (Cortex-M3/M4/M7/M33): thanh ghi DWT->CYCCNT đếm từng chu kỳ CPU. Đo chính xác tới từng chu kỳ:

static inline void cyccnt_init(void) {
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;     /* bật khối trace/debug */
    DWT->CYCCNT = 0;
    DWT->CTRL  |= DWT_CTRL_CYCCNTENA_Msk;               /* bật bộ đếm chu kỳ */
}

uint32_t t0 = DWT->CYCCNT;
control_loop_step();
uint32_t cycles = DWT->CYCCNT - t0;                     /* phép trừ không dấu: đúng khi tràn */
if (cycles > g_max_cycles) g_max_cycles = cycles;       /* ghi lại xấu nhất quan sát được */

Ở 168 MHz, 1 µs = 168 chu kỳ. (Cortex-M0/M0+ không có DWT CYCCNT; dùng SysTick hoặc timer phần cứng chạy ở clock CPU.) Trên Cortex-M7 và một số chip, có thể phải mở khóa DWT bằng thanh ghi LAR trước.

GPIO + oscilloscope / logic analyzer: bật một chân khi vào đoạn code, tắt khi ra. Không cần debugger, thấy được cả jitter (dao động thời gian) và quan hệ với tín hiệu phần cứng khác (ngắt ADC, xung PWM). Đây là cách đo "chân thật" nhất.

Trace RTOS (SEGGER SystemView, Percepio Tracealyzer): timeline của task, ISR, thời gian CPU mỗi task.

Linux: perf, ftrace, clock_gettime(CLOCK_MONOTONIC), và cyclictest để đo độ trễ lập lịch (latency) với kernel PREEMPT_RT.

Đo không đủ: WCET thật

Đo chỉ cho xấu nhất quan sát được, có thể bỏ sót trường hợp xấu hơn không xuất hiện khi test. Các cách tiếp cận:

  • Measurement-based: đo dưới nhiều tình huống, kể cả cố tình tạo tải xấu (mọi ngắt cùng đến, cache bị xóa), cộng thêm biên an toàn (ví dụ 20–50%).
  • Static analysis: công cụ (aiT của AbsInt, Bound-T) phân tích mã máy và mô hình CPU để tính cận trên WCET. Dùng trong hệ thống an toàn cao (hàng không, ô tô).
  • Thiết kế cho phân tích được: vòng lặp có cận trên rõ ràng, không đệ quy, không cấp phát động, ít nhánh phụ thuộc dữ liệu. Đây cũng là tinh thần của MISRA và các quy tắc lập trình an toàn (ví dụ "Power of 10" của NASA/JPL).

Ngân sách CPU và ISR

Một cách lập luận đơn giản: liệt kê mọi tác vụ định kỳ với chu kỳ Tᵢ và WCET Cᵢ; mức sử dụng CPU U = Σ Cᵢ/Tᵢ. Với lập lịch rate monotonic (priority cao cho chu kỳ ngắn), đảm bảo đúng hạn nếu U ≤ n(2^(1/n) − 1) (khoảng 69% khi n lớn); với EDF (earliest deadline first), giới hạn là 100%. Thực tế thiết kế thường giữ U dưới 60–70% để có chỗ cho ngắt và thay đổi về sau. (Module 10 bàn sâu về lập lịch.)

Với ISR: thời gian chạy của mọi ISR ưu tiên cao hơn cộng lại là độ trễ tối đa mà một ISR ưu tiên thấp có thể chịu. Giữ ISR ngắn: đọc phần cứng, đẩy dữ liệu vào ring buffer, báo cho task, xong (Module 9, Bài 2).

Góc EmbeddedVí dụ ngân sách

Vòng điều khiển dòng điện chạy trong ISR ADC ở 20 kHz (chu kỳ 50 µs), MCU 170 MHz (8500 chu kỳ mỗi chu kỳ ISR). Đo WCET của ISR bằng CYCCNT được 3200 chu kỳ (≈ 19 µs): chiếm 38% CPU. Còn lại 62% cho task giao tiếp và giám sát, và phải đảm bảo không ISR nào khác có priority cao hơn ISR này chạy quá vài µs.

Bit

01Đọc giá trị gia tốc 12-bit bù hai từ hai thanh ghi 8-bit (MSB, LSB với 4 bit dữ liệu cao) thế nào?Hay hỏi

Ghép raw = (msb << 4) | (lsb >> 4) (tùy datasheet), rồi mở rộng dấu từ 12 lên 32 bit: m = 1u << 11; v = (int32_t)((raw ^ m) − m). Hoặc dùng lệnh SBFX. Sau đó nhân hệ số thang đo.

02Đếm số bit 1 trong một số 32-bit. Có những cách nào?

Vòng x &= x − 1 (số vòng bằng số bit 1); bảng 256 phần tử theo byte; SWAR (cộng song song trong thanh ghi, không bảng, không vòng lặp); __builtin_popcount / std::popcount. Cortex-M không có lệnh popcount nên builtin sinh mã phần mềm.

03__builtin_clz(0) trả về gì?

Undefined behavior. Phải kiểm tra khác 0 trước. std::countl_zero(0u) của C++20 thì định nghĩa rõ là 32. (Lệnh CLZ của ARM trả 32 với đầu vào 0, nhưng compiler được phép tối ưu dựa trên giả định đầu vào khác 0.)

04Gray code dùng để làm gì?

Hai giá trị liên tiếp chỉ khác một bit, tránh đọc sai khi nhiều bit đổi cùng lúc: encoder quay, bộ đếm/con trỏ FIFO qua hai clock domain. gray = b ^ (b >> 1).

CRC

05CRC hoạt động thế nào? Vì sao tốt hơn checksum cộng?Hay hỏi

Coi dữ liệu là đa thức hệ số 0/1, chia cho đa thức sinh trong số học modulo 2 (XOR), lấy phần dư. CRC n bit phát hiện mọi lỗi 1 bit, mọi burst ≤ n bit, mọi lỗi số bit lẻ (nếu đa thức có thừa số x+1), và đa số lỗi khác với xác suất lọt ~2^−n. Checksum cộng không phát hiện đổi thứ tự byte và các lỗi bù nhau.

06Những tham số nào xác định một thuật toán CRC?Hay hỏi

width, poly, init, refin, refout, xorout; kiểm tra bằng giá trị check của chuỗi "123456789" (CRC-32: 0xCBF43926, CRC-16/CCITT-FALSE: 0x29B1, CRC-16/MODBUS: 0x4B37). Thêm thứ tự byte khi ghi CRC vào gói.

07Cài đặt CRC dùng bảng 256 phần tử hoạt động thế nào?

Tác động của một byte lên thanh ghi CRC chỉ phụ thuộc vào byte đó XOR với byte cao (hoặc thấp, nếu reflected) của thanh ghi; tính sẵn 256 kết quả. Mỗi byte: crc = (crc >> 8) ^ table[(crc ^ b) & 0xFF] (reflected). Nhanh ~8 lần bản từng bit, tốn 1 KB (CRC-32). Bảng 16 phần tử là thỏa hiệp cho MCU ít Flash.

08CRC có dùng để chống giả mạo firmware được không?

Không: kẻ tấn công tính lại CRC dễ dàng. CRC chỉ phát hiện lỗi ngẫu nhiên. Chống giả mạo cần HMAC hoặc chữ ký số (ECDSA/Ed25519) trong secure boot.

Fixed-point và lọc

09Fixed-point Q15 là gì? Nhân hai số Q15 thế nào?Hay hỏi

Số nguyên 16-bit có dấu biểu diễn giá trị/2^15 trong [−1, 1). Nhân: tích 32-bit (Q2.30), cộng 1<<14 để làm tròn, dịch phải 15, bão hòa (vì (−1)×(−1) = +1 không biểu diễn được). Cortex-M4 có lệnh DSP và SSAT hỗ trợ.

10Khi nào dùng fixed-point thay vì float?

MCU không có FPU (M0/M3), cần kết quả giống từng bit giữa nền tảng, cần thời gian tất định trong ISR, hoặc tận dụng SIMD 16-bit của M4. Có FPU single precision thì float dễ đọc hơn; luôn dùng hậu tố f và -Wdouble-promotion.

11Viết bộ lọc thông thấp đơn giản cho ADC không dùng float.Hay hỏi

EMA: acc += x − (acc >> k), đầu ra y = acc >> k (lưu trạng thái với k bit thập phân để không bị kẹt), α = 1/2^k. Một biến trạng thái, O(1). Muốn loại spike thì đặt median 3 trước EMA.

12Moving average O(1) cài đặt thế nào?

Ring buffer N mẫu + tổng chạy: cộng mẫu mới, trừ mẫu cũ nhất bị đẩy ra; chia N (N lũy thừa 2 thì dịch bit). Tổng đủ rộng để không tràn.

13Thiết kế debounce cho nút bấm.Hay hỏi

Lấy mẫu định kỳ (ví dụ mỗi 5 ms trong timer tick), dùng bộ đếm tích phân kẹp [0, MAX] hoặc thanh ghi dịch; chỉ đổi trạng thái khi đủ số mẫu ổn định liên tiếp lớn hơn thời gian dội (5–20 ms). Phát hiện cạnh bằng so với trạng thái trước. Tránh ngắt cạnh + delay trong ISR.

14Hysteresis là gì? Khi nào cần?

Hai ngưỡng khác nhau cho chiều tăng và giảm để đầu ra không bật tắt liên tục khi tín hiệu nhiễu quanh ngưỡng: điều khiển quạt theo nhiệt độ, cảnh báo pin yếu, phát hiện mức. Độ rộng vùng > biên độ nhiễu.

Thời gian và hiệu năng

15Bộ đếm ms 32-bit tràn sau bao lâu? Viết kiểm tra timeout đúng.Hay hỏi

~49,7 ngày. Đúng: if ((uint32_t)(now() − start) >= timeout). Sai: if (now() >= start + timeout) (start + timeout có thể tràn). So sánh hai thời điểm: (int32_t)(a − b) >= 0 (đúng nếu cách nhau < 2^31).

16Quản lý hàng nghìn software timer hiệu quả thế nào?

Timer wheel: mảng N slot, mỗi slot một danh sách; start đặt vào slot (cur + d) % N kèm số vòng; mỗi tick xử lý một slot. Start/stop/tick O(1). Khoảng dài: wheel nhiều tầng. Ít timer thì danh sách sắp xếp hoặc delta list là đủ.

17Viết binary search đúng.

Khoảng nửa mở [lo, hi), mid = lo + (hi − lo)/2 (tránh tràn), if (a[mid] < key) lo = mid + 1; else hi = mid; dừng khi lo == hi. Kết quả là lower bound.

18Chuyển giá trị ADC của NTC sang nhiệt độ thế nào?

Bảng điểm mẫu (ADC, nhiệt độ) từ datasheet/hiệu chuẩn, tìm đoạn chứa giá trị, nội suy tuyến tính. Điểm cách đều 2^k thì chỉ số và phần dư lấy bằng dịch bit/mask, không cần chia. Có thể dùng phương trình Steinhart-Hart nếu có FPU.

19Đo thời gian thực thi của một hàm trên Cortex-M thế nào?Hay hỏi

Bật DWT CYCCNT (TRCENA trong DEMCR, CYCCNTENA trong DWT->CTRL), đọc trước và sau, trừ không dấu; ghi lại giá trị max. Hoặc toggle GPIO và đo bằng oscilloscope/logic analyzer (thấy cả jitter). M0 không có CYCCNT: dùng timer phần cứng.

20WCET là gì? Đảm bảo nó thế nào?

Thời gian thực thi xấu nhất. Đo dưới tải xấu có chủ đích + biên an toàn, hoặc phân tích tĩnh (aiT). Thiết kế cho phân tích được: vòng lặp có cận, không đệ quy, không cấp phát động, chờ phần cứng luôn có timeout, ISR ngắn.
